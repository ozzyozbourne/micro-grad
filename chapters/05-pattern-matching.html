CHAPTER 05UPat, PatternMatcher & graph_rewrite

tinygrad has no "pass manager" full of hand-written tree walkers. Nearly every compiler pass, from scheduling and rangeify to symbolic simplification, devectorizing, decompositions, rendering C, and even compiling the patterns themselves, is the same three-piece machine: a list of (pattern, function) rules (a PatternMatcher), a pattern language (UPat), and one engine that applies the rules to a whole graph until nothing changes (graph_rewrite). This chapter builds that machine up from a four-rule toy, then takes the real one apart down to its stack discipline. A JavaScript port of it, checked against 20 real traces, lets you step through it.

5.1Intuition: find-and-replace for graphs

You know find-and-replace for text, and regexes with capture groups: s/(\w+) \* 1/\1/. Graph rewriting is the same idea over a DAG: a pattern describes a small subgraph shape with named holes, and a function receives whatever filled the holes and returns a replacement subgraph, or None for "never mind". The engine's job is to find every place a pattern applies, including places that only appear after another rewrite, and to rebuild the graph around the replacements.

Analogy: algebra homework When you simplify \( (x\cdot 1 + (2+3))\cdot(1+0) \) by hand, you apply a few identities (\(x\cdot1=x\), \(x+0=x\), "add numbers") wherever they fit, innermost first, until none fits: \(x+5\). The identities are the PatternMatcher. "Innermost first, repeat until nothing changes" is graph_rewrite. tinygrad's compiler is thousands of such identities, organised into ~40 named rewrite passes.
Why build a compiler this way?
  • Rules are local and declarative. Each rule states one fact about one shape. Adding an optimization means appending a tuple, not threading a new case through a visitor.
  • Composition is +. sym = symbolic + pm_simplify_valid + PatternMatcher([...]). Passes are mixed and matched per stage.
  • One engine means one set of guarantees: fixed point, hash-consed sharing preserved, cycle detection, tracing for VIZ, and match statistics, all for free in every pass.

5.2UPat: the pattern language

A UPat mirrors a UOp's fields, but every field is a constraint (None = "anything"):

fieldmeaning
opan Ops, or a tuple/set of them (e.g. GroupOp.ALU); stored as a tuple
dtypea DType or a tuple of DTypes (stored as match_dtype)
srctuple: match the sources in this order · list: try every permutation (commutative ops) · a single UPat: every source must match it, any number of them
argmust equal the node's arg
namebind the matched UOp to this keyword for the function. The same name used twice must bind the same object (hash-consing makes that an is check)
allow_any_lenthe tuple is a prefix: extra sources are allowed
locationfile:line where the UPat was written, recorded automatically for match stats and VIZ

Shorthands: UPat.var("x") = UPat(name="x") (anything); UPat.cvar("c") = a named CONST; UPat.const(dt, 0)/UPat.cvar(arg=1) = a specific constant; UPat.any(a, b) = alternatives; .or_casted(), .or_after(). And the operator DSL: UPat inherits the same operator mixin as Tensor and UOp (tinygrad/mixin/elementwise.py), so UPat.var("x") + 0 runs the exact same __add__ → _binop → alu path. UPat only overrides the last step:

tinygrad/uop/ops.py:1491–1493 — commutative ops get a list src
  def alu(self, op:Ops, *src:UPat):
    asrc = (self,)+src
    return UPat(op, dtypes.bool if op in GroupOp.Comparison else asrc[-1].match_dtype, list(asrc) if op in GroupOp.Commutative else asrc)

So UPat.var("x") * 1 also matches 1*x, with no extra rule. The matcher itself (the interpreted version) is short:

tinygrad/uop/ops.py:1495–1511 — UPat.match
  def match(self:UPat, uop:UOp, store:dict[str, UOp]) -> list[dict[str, UOp]]:
    if self.is_any: return flatten([x.match(uop, store.copy()) for x in self.src[0]])
    if (self.op is not None and uop.op not in self.op) or \
       (self.name is not None and store.setdefault(self.name, uop) is not uop) or \
       (self.match_dtype is not None and uop.dtype not in self.match_dtype) or \
       (self.arg is not None and self.arg != uop.arg) or \
       (len(uop.src) < self.required_len) or \
       (self.strict_length and len(uop.src) != self.required_len): return []
    if self.src is None: return [store]
    res: list[dict[str, UOp]] = []
    for vp in self.src:
      stores, new_stores = [store.copy()], []
      for uu, vv in zip(uop.src, vp):
        for s in stores: new_stores.extend(vv.match(uu, s))
        stores, new_stores = new_stores, []
      res.extend(stores)
    return res

It returns a list of bindings (one per way the pattern fits), each a dict name → UOp. Note store.setdefault(self.name, uop) is not uop: that line enforces "same name, same object".

early_reject is a cheap prefilter computed from the pattern. Here the pattern needs a CONST among the sources, so a MUL whose sources contain no CONST is rejected before any matching code runs.

5.3PatternMatcher: rules indexed by op

A PatternMatcher is a list of (UPat, fxn). At construction it builds pdict, a map from each op to the list of rules whose root can be that op. Rewriting one node then means: look up the node's op, skip rules whose early_reject set isn't contained in the node's source ops, and try the rest in order. The first rule whose function returns something other than None (and other than the node itself) wins.

tinygrad/uop/ops.py:1544–1568
class PatternMatcher:
  def __init__(self, patterns:Sequence[tuple[UPat, Callable|tuple]], compiled=bool(getenv("UPAT_COMPILE", 1))):
    # if this comes from a pickle, we reconstruct the lambda functions here
    self.patterns:list[tuple[UPat, Callable]] = [(p,types.FunctionType(*fxn) if isinstance(fxn, tuple) else fxn) for p,fxn in patterns]
    # NOTE: use of DefaultDict here is very dangerous! all keys will live for the lifetime of the PatternMatcher!
    self.pdict: dict[Ops, list[list]] = {}
    # uop is required, arg is optional
    for p,fxn in self.patterns:
      assert p.op is not None
      entry: list = [p, None, p.early_reject]
      entry[1] = upat_deferred_compile(p, fxn, entry) if compiled else upat_interpret(p, fxn)
      for uop in p.op: self.pdict.setdefault(uop, []).append(entry)

  def __reduce__(self): return PatternMatcher, ([(x,deconstruct_function(fxn) if fxn.__name__ == "<lambda>" else fxn) for x,fxn in self.patterns],)

  @functools.cache  # pylint: disable=method-cache-max-size-none
  def __add__(self, more:PatternMatcher) -> PatternMatcher: return PatternMatcher(self.patterns+more.patterns)

  def rewrite(self, uop:UOp, ctx=None):
    if len(pats:=self.pdict.get(uop.op, [])):
      if (ler:=uop.__dict__.get('_src_ops')) is None: uop.__dict__['_src_ops'] = ler = {u.op for u in uop.src}
      for _,match,early_reject in pats:
        if not early_reject.issubset(ler): continue
        if (ret:=match(uop, ctx)) is not None and ret is not uop: return ret
    return None
  • None means "no match, keep trying". A function may decline a match after inspecting it (e.g. "only if the constant fits in the dtype"). Many real rules are lambda ...: X if condition else None.
  • Rule order matters within an op. In symbolic_simple, the cheap identities come before the general folders.
  • A function can take a ctx keyword. If it does, it receives the context object passed to graph_rewrite (5.8).
  • __add__ concatenates pattern lists and is functools.cached, so symbolic+pm_x built in a hot path is created once.

5.5Under the hood: UPats compile to Python source

Interpreting UPat.match for every rule on every node is slow, since patterns are tried millions of times per model. So by default (UPAT_COMPILE=1) each rule is compiled to a Python function. Compilation is lazy: a rule's slot in pdict starts as a stub that compiles the real matcher on its first call, overwrites itself (entry[1] = …), and runs it:

tinygrad/uop/ops.py:1537–1542
def upat_deferred_compile(p:UPat, fxn:Callable, entry:list) -> Callable:
  def lazy_compile(uop, ctx):
    from tinygrad.uop.upat import upat_compile
    entry[1] = upat_compile(p, fxn)
    return entry[1](uop, ctx)
  return lazy_compile

The compiler in tinygrad/uop/upat.py uses tinygrad's own machinery on itself. _get_clause turns a UPat into a UOp graph of predicates: AND/OR nodes, CUSTOM nodes holding format strings such as "{0}.op is {1}", STORE for name bindings, INDEX for "src[i] of", and PYLITERAL for Python constants. Then two PatternMatchers rewrite that graph: pm_proc flattens nested ANDs, multiplies out ORs (one per permutation) and turns duplicate name bindings into is checks; pm_renderer collapses everything into strings. _final_render prints if …: return _ret lines, and the result is exec'd. This is where CUSTOM, CUSTOMI and PYLITERAL from the Ops atlas (Ch 4) live.

Read the first function: the list src of x*1 became two if lines, one per permutation, tried in written order first. Constants were hoisted into globals (a0, a1), so the check is an identity test. The bound names become keyword arguments to _fxn, the user's lambda. Patterns too complex to compile (≥4 OR-clauses) raise UPatCompileError and need compiled=False, which uses the interpreter upat_interpret.

Both are built with compiled=False, since compiling the compiler's own patterns would recurse. The match statistics in 5.10 show these rules are among the most frequently fired in a whole run, because every user rule gets compiled the first time it's needed.

5.6graph_rewrite and the unified_rewrite algorithm

tinygrad/uop/ops.py:1847–1854
@rewrite_group(new_ctx=False)
def graph_rewrite(sink:UOp, pm:PatternMatcher, ctx=None, bottom_up=False, name=None, bpm=None, walk=False, enter_calls=False,
                  init_ctx:type|None=None) -> UOp:
  if init_ctx is not None:
    assert ctx is None
    ctx = init_ctx()
  rewrite_ctx = RewriteContext(pm if not bottom_up else None, pm if bottom_up else bpm, ctx, enter_calls)
  return rewrite_ctx.walk_rewrite(sink) if walk else rewrite_ctx.unified_rewrite(sink)

The arguments: pm is the matcher. bottom_up=True means "use pm as the bottom-up matcher bpm instead of the top-down pm"; you can also pass both, pm plus an extra bpm=. ctx (or init_ctx, a class to instantiate) is handed to rules. walk=True switches to the single-pass driver. enter_calls makes the engine descend into CALL bodies (normally a kernel's AST is opaque to graph-level passes). name labels the pass in VIZ. All state lives in a RewriteContext: replace: dict[UOp, UOp], the memo "this original node has finished rewriting into that node", plus a cache for the bottom-up matcher.

unified_rewrite is an iterative post-order traversal with an explicit stack of (n, stage, new_n) triples (no Python recursion, so 100k-node graphs are fine). Every node passes through up to three stages:

stage 0 · descend
If there is a bottom-up matcher, apply it to n repeatedly until it returns None (a fixed point; a repeated node raises infinite loop in fixed_point_rewrite). Then push (n, 1, new_n) and push the srcs of new_n (reversed, skipping any already on the stack) for stage 0.
stage 1 · rebuild
All srcs should now be in replace. If one isn't, park this entry in a waitlist keyed on that src. If no src changed, run the top-down matcher pm on the node. No match → done, replace[n] = new_n. If srcs changed, build the new node from the rewritten srcs. Either way, the result goes back through stage 0 and (n, 2, result) waits for it.
stage 2 · link
When the result has finished its own rewriting, replace[n] = replace[result]. That is the fixed point: a replacement is itself rewritten until nothing matches. Finishing a node releases everything on its waitlist.
tinygrad/uop/ops.py:1776–1845
  def unified_rewrite(self, root:UOp) -> UOp:
    stack: collections.deque[tuple[UOp, int, UOp]] = collections.deque([(root, 0, root)])
    on_stack = {root}  # all UOps either on the stack or in self.replace, i.e. dont have to be placed again
    waitlist: dict[UOp, list[tuple[UOp, int, UOp]]] = {}  # UOps waiting on a dependency to be in self.replace
    while stack:
      if len(stack) > REWRITE_STACK_LIMIT: raise RuntimeError("infinite loop in graph_rewrite (stack too big)")
      n, stage, new_n = stack.pop()
      if n in self.replace: continue  # skip any nodes we have seen
      if stage == 0:
        # if bottom up, we rewrite this node early. in both cases, we add its srcs to the stack
        if self.bpm is not None:
          # apply rewrite rules until a fixed point is reached. may return `uop` itself if PatternMatcher doesn't match
          test_n: UOp|None = n
          seen = set()
          try:
            while test_n is not None:
              if test_n in seen: raise RuntimeError("infinite loop in fixed_point_rewrite")
              seen.add(test_n)
              new_n, test_n = test_n, self.cached_bpm_rewrite(test_n)
          except BottomUpGate:
            # if the bpm matching raised a gate, we are done with this node and dont continue down the srcs
            self.replace[n] = unwrap(test_n)
            if n in waitlist: stack.extend(waitlist.pop(n))
            continue
        stack.append((n, 1, new_n))
        # NOTE: CALLs are handled as a special case: their bodies are not included in the graph_rewrite,
        # rewrites that need them pass enter_calls=True
        for x in reversed(new_n.src[1:] if new_n.op is Ops.CALL and not self.enter_calls else new_n.src):
          if x in on_stack: continue
          stack.append((x, 0, x))
          on_stack.add(x)
      elif stage == 1:
        skip = int(new_n.op is Ops.CALL and not self.enter_calls)
        tmp = list(new_n.src[:skip])
        for x in new_n.src[skip:]:
          if (rx:=self.replace.get(x, SENTINEL)) is SENTINEL:
            # source not ready: register in waitlist instead of spinning
            waitlist.setdefault(x, []).append((n, 1, new_n))
            break
          tmp.append(rx)
        else:
          # in stage 1, once all srcs are rewritten, rebuild (if changed) or run top-down rewrite
          if (new_src:=tuple(tmp)) == new_n.src:
            # if top down, do the rewrite. if no rewrite or bottom up, we are done rewriting this node so we add it to the dict
            if self.pm is None or (new_src_n:=self.pm_rewrite(new_n)) is None:
              self.replace[n] = new_n
              if n in waitlist: stack.extend(waitlist.pop(n))
              continue
          else:
            # if srcs changed from rewrites, construct a new UOp with the new srcs
            new_src_n = UOp(new_n.op, new_src, new_n.arg)
          # trigger a rewrite of new_src_n, then after that rewrite is done, link it back to n
          stack.append((n, 2, new_src_n))
          stack.append((new_src_n, 0, new_src_n))
      else:
        # in stage 2, we link the result of new_n to the result of n
        if (replaced_new_n:=self.replace.get(new_n, SENTINEL)) is SENTINEL:
          # not ready: register in waitlist instead of spinning
          waitlist.setdefault(new_n, []).append((n, 2, new_n))
        else:
          # otherwise we are done
          self.replace[n] = replaced_new_n
          if n in waitlist: stack.extend(waitlist.pop(n))
    if root not in self.replace:
      def label(u:UOp) -> str: return f"{u.op.name}@{id(u):x}"
      details = [f"  {label(n)} -> {label(new_n)} waits for {label(dep)}"
                 for dep, waiters in itertools.islice(waitlist.items(), 5) for n, _, new_n in waiters[:1]]
      raise RuntimeError("graph_rewrite stalled: unresolved rewrite dependencies (possible cycle). "
                         "A replacement may depend on the node being rewritten.\n" + "\n".join(details))
    return self.replace[root]
Two subtle consequences you can see in the traces below: (1) in default mode an original node whose sources changed is never matched itself. Only its rebuilt version is. In E1, (x*1+(2+3)) is never tried; (x+5) is. (2) pm_rewrite is not cached, but each UOp reaches it at most once, because the replace check at the top skips finished nodes. Hash-consing means a subexpression shared by many parents is rewritten exactly once.

5.7Top-down vs bottom-up, and why the names look backwards

Look at the two traces again. In default mode (pm, called "top-down" in the source comments), a node is matched after all its sources are finished: {}, x, 1, then (x*1). The names make sense in tinygrad's VIZ, which draws graphs with sources on top and the SINK at the bottom. "Bottom-up" starts at the sink and works up toward the inputs. 5.8Fixed points, walk, cycles and ctx

=== 5. fixed point: a rewritten node is rewritten again (unless walk=True) ===
graph_rewrite(x*4)            -> (x+x+(x+x))
graph_rewrite(x*4, walk=True) -> (x*2*2)  (single pass, no re-traversal of the replacement)

With the default driver, x*4 → (x*2)*2 is not the end: the new node goes back through the engine, its inner x*2 becomes x+x, the outer (x+x)*2 becomes (x+x)+(x+x), and since hash-consing makes the two x+x one node, the result is a DAG with 2 ADDs, not a tree of 3. With walk=True (walk_rewrite) the replacement is final, which is cheaper and sometimes exactly what a pass wants.

The fixed point has a price: rule sets must be terminating. Two rules that undo each other loop forever. The engine detects this in two ways, and the captured runs of x+x under rules {x+x → x*2, x*2 → x+x} show both:

ctx: state shared between rules

=== 6. ctx: rules can read/write shared state (here: count the CONSTs we fold) ===
result: 10  ctx after: [3, 6, 10]

A rule function that declares a ctx parameter receives graph_rewrite(..., ctx=…). Real passes use it for lookup tables and accumulation: _substitute's ctx is the replacement dict; the renderer's ctx maps UOps to already-rendered strings; rangeify's ctx is an IndexingContext; init_ctx=MapCtx or CountCtx creates a fresh dict or counter per call. Since the engine is deterministic, the order of side effects is well-defined: here [3, 6, 10], innermost first.

In default mode, you rewrite ((x*1)+(2+3))*(1+0) with the four toy rules. Which node is never passed to the matcher?
Its srcs changed (x*1→x, 2+3→5), so stage 1 builds the new node (x+5) and sends that to stage 0. The original is linked to the result in stage 2 without ever being matched. You can see the gap between calls 7 and 8 of the real trace.
A rule returns the node it was given (return x where x is the root). What does PatternMatcher do?
if (ret:=match(uop, ctx)) is not None and ret is not uop: return ret, so returning self means "no change".
You need a pass that replaces every RESHAPE of a buffer before the pass recurses into that buffer's subgraph (the parent decides what the child becomes). Which mode?
bottom_up matches a node before its sources are visited, so the rule sees the original subgraph. With confluent rules the final fixed point is often the same, but many tinygrad passes are not confluent and rely on order.

  # resolve UNSHARDs (multi-device UNSHARDs are already resolved by the scheduler; this handles in-kernel shards, e.g. fragments)
  sink = graph_rewrite(ast, multi_pm, name="multi_pm")

  # preprocess
  sink = graph_rewrite(sink, pm_mops, name="early movement ops", bottom_up=True)

  # first we optimize
  if optimize:
    # collapse loads reduce (indexing by a tensor)
    sink = graph_rewrite(sink, pm_load_collapse, name="load collapse")

    # split ranges
    sink = graph_rewrite(sink, pm_split_ranges+pm_flatten_range, init_ctx=MapCtx, name="split ranges")

    # symbolic (NOTE: this is a requirement for pm_simplify_ranges to be correct)
    sink = graph_rewrite(sink, sym+pm_flatten_range, name="initial symbolic")

    # optimize (schedule) the AST
    sink = graph_rewrite(sink, pm_flatten_range+pm_simplify_ranges, init_ctx=MapCtx, name="simplify ranges")

    # do postrange optimization, BEAM or hand_coded_optimizations
    sink = apply_opts(sink, ren, beam=ast.arg.beam)

  sink = graph_rewrite(sink, sym+pm_move_where_on_load+pm_flatten_range+pm_reduce_unparented, name="postopt symbolic")

5.10Watching it work: TRACK_MATCH_STATS, rewrite_group, VIZ

Because every pass goes through graph_rewrite, instrumenting that one function instruments the whole compiler:

  • TRACK_MATCH_STATS=1 swaps PatternMatcher for TrackedPatternMatcher at import time, which counts attempts, matches and time per UPat. At exit, print_match_stats prints the table (disable it with PRINT_MATCH_STATS=0).
  • TRACK_MATCH_STATS=2 (the default when VIZ is set) also records, for every graph_rewrite, the input graph and each match (before node, after node, rule location, time) into tracked_ctxs, grouped by @rewrite_group (ops.py:1618) into named groups like "Schedule 1 → 1" and one group per kernel. UOps are serialized compactly through trace_num. A rule that raises is recorded as a REWRITE_ERROR node.
  • VIZ=1 opens the browser viewer on that data. VIZ=-1 just saves it, and python -m tinygrad.viz.cli -q 'initial symbolic' prints any pass's graph in the terminal (that's how the ch04 data was explored). Chapter 21 covers this tooling.

5.11Hammer it: rules returning None vs a UOp, one more time

Each rule application ends one of three ways, and the engine treats them differently:

Nonetry the next rule for this opif no rule matches: replace[n] = n, done

A useful mental model: a PatternMatcher is a partial function UOp → UOp, and graph_rewrite computes its normal form on every node of the DAG. That is well-defined as long as the rules terminate, and unique when they're confluent.

Why doesn't graph_rewrite recurse in Python?
Same reason as toposort and recursive_property in Chapter 4. The REWRITE_STACK_LIMIT is a guard against infinite loops, not against depth.
You write (UPat.var("x") + UPat.var("y"), lambda x,y: ...). How many source orders will the compiled matcher try for one ADD node?
Only when the list holds the same UPat twice (e.g. var("x")+var("x"), the same cached object) does UPat.__init__ skip permutations (all_same(src)).
What does UOp.substitute({a: b}) run under the hood?
ops.py:506 and ops.py:1860. bottom_up so that the dict is consulted on original nodes before their children change.

Chapter summary

  • UPat = a UOp with holes: op/dtype/arg constraints, tuple src (ordered), list src (all permutations, created automatically for commutative ops by the operator DSL), single-UPat src (repeat), names that bind and must agree.
  • PatternMatcher = ordered rules indexed by op in pdict, with an early_reject prefilter. A function returning None (or the node itself) means "next rule". Matchers compose with +.
  • UPats are compiled lazily into Python source by upat.py, a mini-compiler that represents predicates as UOps and rewrites them with two PatternMatchers.
  • graph_rewrite → unified_rewrite: explicit-stack post-order traversal in three stages (descend / rebuild+match / link), a replace memo, and a waitlist. The default pm matches after sources are done, bottom_up matches before, and both reach a fixed point. walk=True is a single pass without one. Loops are caught by REWRITE_STACK_LIMIT or the fixed-point seen set.
  • ctx/init_ctx give rules shared state. enter_calls opens CALL bodies. name, rewrite_group and TRACK_MATCH_STATS/VIZ make every pass observable.
  • Next, Chapter 6 looks at the biggest rule set: integer algebra and range analysis.
