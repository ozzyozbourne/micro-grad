CHAPTER 03dtypes & type promotion

Every UOp has a dtype, and the dtype decides what C type a value gets, how many bytes a buffer holds, which ALU instruction is emitted, and what happens when an int8 meets a float16. This chapter covers the DType object, the promotion lattice that decides a + b's type, the weak types that let Python literals adapt to their neighbours, the difference between casting and bitcasting, and what codegen does when the hardware can't handle a dtype at all.

All outputs are from tinygrad commit 6a404871 on DEV=CPU (clang). If you know older tinygrad, several things are gone. PtrDType, ImageDType and DType.vec()/.scalar()/.count no longer exist. Pointer-ness lives in the op (PARAM/INDEX) and address spaces in the AddrSpace enum. Vector width lives in the shape of the UOp. Images are recognised by shape (is_image_shape: 3 dims, last = 4). The dtype is no longer a field of the UOp either; it is computed from (op, src, arg) (3.8).

3.1Why a compiler cares so much

In NumPy, dtype is a property of an array in memory. In tinygrad, most values never touch memory: they live in registers inside a fused kernel. The dtype is a property of every node in the graph, and it has to be right at every node, because the renderer turns each one into a typed C expression: (signed char)(-24), (__fp16)(0.5f), float4.

Analogy: containers in a kitchen A dtype is the container a value is kept in: a shot glass (int8), a mug (int32), a bucket (float64). When you pour two containers together you need one that holds both: that is promotion. A Python literal like 1.5 arrives as liquid without a container (a weak type). It takes the shape of whatever it is poured into, and only gets its own container (DEFAULT_FLOAT) if it is served alone.

The rules in this chapter answer three questions that every graph_rewrite and the renderer depend on:

  1. What dtypes exist, and what do they know about themselves? (3.2, 3.3)
  2. When two dtypes meet, which wins? (3.4, 3.5, 3.6, 3.7)
  3. How does a node get its dtype, and how is a dtype the hardware lacks handled? (3.8–3.11)

3.2The DType object

# all DTypes should only be created once
class DTypeMetaClass(type):
  dcache: dict[tuple, DType] = {}
  def __call__(cls, *args, **kwargs):
    if (ret:=DTypeMetaClass.dcache.get(args, None)) is not None: return ret
    DTypeMetaClass.dcache[args] = ret = super().__call__(*args)
    return ret

@dataclass(frozen=True, eq=False)
class DType(metaclass=DTypeMetaClass):
  priority: int  # this determines when things get upcasted
  bitsize: int
  name: str
  fmt: FmtStr|None
  @property
  def itemsize(self) -> int: return (self.bitsize + 7) // 8
  def __repr__(self): return f"dtypes.{self.name}"
  def __lt__(self, o:DType): return (self.priority, self.bitsize, self.name, self.fmt) < (o.priority, o.bitsize, o.name, o.fmt)
  @functools.cached_property
  def min(self): ...     # 0 / -2**(bits-1) for ints, -max for floats
  @functools.cached_property
  def max(self): ...     # 2**bits-1+min for ints, inf (or the largest normal for e4m3 / fnuz fp8s) for floats
  def const(self, val): ...  # canonicalize a Python value to this dtype: truncate ints, ConstFloat for floats
  • Four fields. priority orders dtypes (it is what min() in least_upper_dtype compares first). bitsize gives itemsize (bool is 1 bit, so 1 byte). name is the short name. fmt is the Python struct/memoryview format char: that is how .data() and _frompy pack and unpack. bf16 and fp8 have fmt=None, which is why _frompy packs them as float32 and casts (Chapter 2).
  • Interned. DTypeMetaClass caches every DType by its constructor args, so DType(14, 32, 'f32', 'f') is dtypes.float32. Like UOps, dtypes compare with is, and eq=False keeps the identity-based hash fast.
  • Weak dtypes have bitsize=800. That is a deliberate "wider than anything" sentinel. It has no meaning as a storage size, and creating storage for a weak dtype is an error.

3.4The promotion lattice and least_upper_dtype

When two dtypes meet in a binary op, tinygrad follows JAX's design (JEP 9407). The dtypes form a lattice: a directed graph where an edge a → b means "b can represent every a value well enough". The result of combining two dtypes is their least upper bound: the lowest dtype reachable from both.

promo_lattice = { dtypes.bool: [dtypes.weakint], dtypes.weakint: [dtypes.int8, dtypes.uint8],
  dtypes.int8: [dtypes.int16], dtypes.int16: [dtypes.int32], dtypes.int32: [dtypes.int64],
  dtypes.int64: [dtypes.weakfloat], dtypes.uint8: [dtypes.int16, dtypes.uint16], dtypes.uint16: [dtypes.int32, dtypes.uint32],
  dtypes.uint32: [dtypes.int64, dtypes.uint64], dtypes.uint64: [dtypes.weakfloat],
  dtypes.weakfloat: [dtypes.fp8e4m3, dtypes.fp8e5m2, dtypes.fp8e4m3fnuz, dtypes.fp8e5m2fnuz],
  dtypes.fp8e4m3: [dtypes.float16, dtypes.bfloat16], dtypes.fp8e5m2: [dtypes.float16, dtypes.bfloat16],
  dtypes.fp8e4m3fnuz: [dtypes.float16, dtypes.bfloat16], dtypes.fp8e5m2fnuz: [dtypes.float16, dtypes.bfloat16],
  dtypes.float16: [dtypes.float32], dtypes.bfloat16: [dtypes.float32], dtypes.float32: [dtypes.float64], }

@functools.cache
def _get_recursive_parents(dtype:DType) -> set[DType]:
  return set.union(*[_get_recursive_parents(d) for d in promo_lattice[dtype]], {dtype}) if dtype != dtypes.float64 else {dtypes.float64}
@functools.cache
def least_upper_dtype(*ds:DType) -> DType:
  return min(set.intersection(*[_get_recursive_parents(d) for d in ds]))
def least_upper_float(dt:DType) -> DType:
  return dtypes.weakfloat if dt is dtypes.weakint else dt if dtypes.is_float(dt) else least_upper_dtype(dt, dtypes.default_float)

The algorithm in three steps:

  1. Up-sets. _get_recursive_parents(d) is every dtype reachable from d, including d itself. f64 is the top.
  2. Intersect. The common upper bounds of all inputs. It is never empty, because f64 is reachable from everything.
  3. Take the min. This uses DType.__lt__, i.e. (priority, bitsize, name, fmt). In a true lattice there would be a unique least element. Here the priority breaks ties (f16 vs bf16 both reachable from fp8 → f16 has the lower priority).

Three surprises the lattice explains
  • int64 + uint64 → weakfloat. No integer type holds both ranges. The only common upper bounds are the floats, and the lowest of those is weakfloat, which then commits to DEFAULT_FLOAT (f32).
  • int32 + float16 → f16. A float of any width beats an int of any width. The lattice's int chain feeds into the float chain below f16. JAX does the same, deliberately, so that a half model never silently upcasts.
  • f16 + bf16 → f32. Neither contains the other (f16 has more mantissa, bf16 more exponent), so the join is the next float up.
What is least_upper_dtype(dtypes.uint8, dtypes.int8), and why?
Up-set(u8) = {u8, i16, u16, i32, u32, i64, u64, weakfloat, …floats}. Up-set(i8) = {i8, i16, i32, i64, weakfloat, …}. The intersection's minimum is i16 (priority 3). The example prints least_upper_dtype(i8, u8) = i16.

3.5Weak dtypes: literals have a kind but no width

If 1 were an int32, then int8_tensor + 1 would promote to int32, which is surprising and wasteful. If 0.5 were float32, then half_tensor * 0.5 would upcast every half model. So Python scalars get a weak dtype: dtypes.weakint or dtypes.weakfloat. They sit low in the lattice (weakint just above bool, weakfloat just below the smallest float), so almost any concrete dtype absorbs them.

tinygrad/dtype.py:101 — dtypes.from_py
  def from_py(x) -> DType:
    # NOTE: isinstance(True, int) is True, so bool must be checked before int
    if isinstance(x, (bool, InvalidType)): return dtypes.bool
    if isinstance(x, float): return dtypes.weakfloat
    if isinstance(x, int): return dtypes.weakint
    if isinstance(x, (list, tuple)):
      dt = max(dtypes.from_py(xi) for xi in x) if x else dtypes.weakfloat
      if dt is not dtypes.weakint: return strong_dtype(dt)
      ints = [xi for xi in x if isinstance(xi, int)]  # a vconst also holds Invalid
      return commit_int(min(ints), max(ints))

A scalar stays weak. A list becomes storage, so it must commit immediately: floats → strong_dtype (DEFAULT_FLOAT), ints → commit_int, which picks the first dtype on the ladder (default_int, int32, int64, uint64) that holds the list's min and max. That is why Tensor([2**40]) is i64 and Tensor([2**63]) is u64.

tinygrad/dtype.py:170
def strong_dtype(dtype:DType) -> DType:
  return {dtypes.weakint: dtypes.default_int, dtypes.weakfloat: dtypes.default_float}.get(dtype, dtype)
def commit_int(lo:int|float, hi:int|float, default_int:DType|None=None) -> DType:
  if lo == hi and not dtypes.long.min <= lo <= dtypes.ulong.max: raise OverflowError(f"{lo} does not fit any int")
  ladder = (dtypes.default_int if default_int is None else default_int, dtypes.int, dtypes.long, dtypes.ulong)
  return next((dt for dt in ladder if dt.min <= lo and hi <= dt.max), dtypes.long)
def weak_dtype(dtype:DType) -> DType:
  return dtypes.weakfloat if dtypes.is_float(dtype) else dtypes.weakint if dtypes.is_int(dtype) else dtype

How does the literal adopt its neighbour's dtype? In ElementwiseMixin._broadcasted, which every binary op goes through:

tinygrad/mixin/elementwise.py:24
  def _broadcasted(self, y, reverse=False):
    y = self.ufix(y)
    x, y = (self, y) if not reverse else (y, self)
    out_dtype = least_upper_dtype(x.dtype, y.dtype)
    # keep weak CONST weak, might lift weakint -> weakfloat
    def promote(t):
      if t._uop.base.is_invalid: return t  # invalid bool is weak const
      if t.dtype in dtypes.weaks and t._uop.base.op is Ops.CONST:
        return t if t.dtype == (dt:=weak_dtype(out_dtype)) else t._wrap_uop(remint(t._uop, dt))
      return t.cast(out_dtype)
    return promote(x), promote(y)

The key line is the promote special case. A weak CONST is not cast to out_dtype. It stays weak; at most its kind changes (remint: weakint 1 → weakfloat 1.0 when it meets a float). Everything else is cast. The op's dtype is then computed from its srcs (3.8): least_upper_dtype(i8, weakint) = i8. The literal never got a width in the Tensor graph, yet the ADD is i8.

3.6Where weakness ends: codegen commits every literal

A weak dtype can't be rendered: there is no C type called weakint. Weakness has two exits:

  • Storage (Tensor level). linear_with_vars refuses to realize a weak value on a device. data(), empty_like, full, reductions (_reduce starts with self.cast(self.commit_dtype())) all commit first. "Weakness ends where storage begins", as the comment in linear_with_vars puts it.
  • Codegen (kernel level). Literals inside a kernel stay weak all the way to codegen. full_rewrite_to_sink runs three matchers from tinygrad/uop/weak.py:
    • pm_commit_weak (weak.py:36) rides along with the symbolic, decomposition and final passes (codegen/__init__.py:317, 342, 347). A broadcastable op commits its weak srcs to the op's concrete dtype. A STORE of a weak value casts it to the buffer's dtype.
    • pm_lower_weak (weak.py:72, "lower all index dtypes", :322) settles weak index arithmetic to int/long.
    • pm_cast_const (weak.py:106, "cast consts", :351) is the last step. Any remaining weak CONST gets a concrete type through UOp.cconst.

They are ContextVars, so they can be set from the environment (DEFAULT_FLOAT=HALF python …) or scoped with Context(...). dtypes.default_float is a property that reads the var on every access, so changing it affects everything created afterwards. They decide:

  • what a weak value commits to (strong_dtype, and the first rung of commit_int),
  • the dtype of float lists, Tensor.empty/rand/randn, arange of floats, and the result of int /, sqrt, exp (least_upper_float: an int meets default_float).

3.8dtype is derived: dtype_from_uop

A UOp has three fields, op, src, arg. dtype is a @recursive_property that calls dtype_from_uop(op, src, arg). This is a total set of production rules, one case per kind of op:

tinygrad/uop/ops.py:115 — dtype_from_uop (abridged)
def dtype_from_uop(op:Ops, src:tuple[UOp,...], arg:Any) -> DType:
  # here are the dtype production rules, total over all Ops
  match op:
    case Ops.STORE | Ops.LINEAR | Ops.SINK | Ops.PROGRAM | Ops.SOURCE | ...: return dtypes.void
    case Ops.INDEX: ...                         # the buffer's dtype (images read float)
    case Ops.LOAD | Ops.REDUCE | Ops.AFTER | Ops.COPY | Ops.STAGE | ...: return src[0].dtype   # pass through first
    case Ops.CMPLT | Ops.CMPNE | Ops.CMPEQ: return dtypes.bool
    case Ops.SIN | Ops.LOG2 | Ops.EXP2 | Ops.SQRT | Ops.RECIP:
      return dtypes.bool if src[0].base.is_invalid else least_upper_float(src[0].dtype)
    case Ops.WHERE: return promo_dtype(src[1:])   # cond must be bool
    case Ops.FDIV: return least_upper_float(promo_dtype(src))
    case Ops.BUFFER | Ops.ALLOC | Ops.PARAM: return arg.dtype
    case Ops.CAST | Ops.BITCAST: return arg
    case Ops.CONST:
      # derived from the value. order matters: bool is an int subclass, ConstFloat is a float subclass
      if isinstance(arg, bool): return dtypes.bool
      if isinstance(arg, int): return dtypes.weakint
      if isinstance(arg, float): return dtypes.weakfloat
  if op in GroupOp.Unary: return src[0].dtype
  if op in GroupOp.Broadcastable: return promo_dtype(src)     # same dtype, or least_upper_dtype of the srcs
  if op in GroupOp.Movement: return src[0].dtype

Consequences you can see in the printouts:

  • A CONST is always weak or bool. UOp.const(2, dtypes.float32) returns CAST(CONST(2.0), f32): the width is carried by a CAST (ops.py:601). That is the "typed constant" pair from 3.6.
  • Promotion lives in one place. ADD's dtype is promo_dtype(src). No pass ever has to "update" a dtype after rewriting srcs, and two UOps with the same (op, src, arg) can't disagree on dtype. That is essential for hash-consing.
  • Ops like sqrt promote ints. least_upper_float(i8) = least_upper_dtype(i8, f32) = f32.

  y / 2          -> MUL     dtype=dtypes.f32
  y.cast(f16)    -> CAST    dtype=dtypes.f16
  y.bitcast(u8)  -> BITCAST dtype=dtypes.u8

CONST(2) + CONST(1.5) is an ADD of dtype weakfloat: two weak literals stay weak. y / 2 is a MUL, because division by a constant becomes multiplication by its reciprocal. Chapter 4 lists the op groups (GroupOp.Unary, Broadcastable, …) these rules dispatch on.

You build u = UOp(Ops.CONST, arg=3). What is u.dtype, and where is it stored?
The UOp dataclass fields are ['op', 'src', 'arg'] (printed in section 5). The CONST rule maps an int arg to weakint. To get a concrete int you write UOp.const(3, dtypes.int32), which is a CAST around the CONST.

3.9Casting vs bitcasting

cast converts the value (2.7 → 2). bitcast reinterprets the bits (1.0f → 0x3f800000 → 1065353216). Both are one UOp. CAST and BITCAST carry the target dtype as their arg, and dtype_from_uop returns it.

tinygrad/mixin/dtype.py:19, 38
  def cast(self, dtype:DTypeLike) -> Self:
    return self if self.dtype == (dt:=to_dtype(dtype)) else self._wrap_uop(self._uop.alu(Ops.CAST, arg=dt))
  def bitcast(self, dtype:DTypeLike) -> Self:
    """Bitcasts `self` to the given `dtype`. If the itemsize differs, the last axis is rescaled."""
    dt = to_dtype(dtype)
    if self.dtype in dtypes.weaks or dt in dtypes.weaks: raise RuntimeError(f"bitcast requires concrete dtypes, got {self.dtype} -> {dt}")
    ...

A bitcast needs real bits, so weak types are rejected. Changing the itemsize rescales the last axis: 4 floats → 16 bytes. For a single scalar, dtype.bitcast(x, in, out) does the same in pure Python with struct, and dtype.truncate[dt] rounds a Python value to a dtype. 3.10Accumulators and lossless casts

tinygrad/dtype.py:214
def sum_acc_dtype(dt:DType):
  # default acc dtype for sum
  if dtypes.is_unsigned(dt): return least_upper_dtype(dt, dtypes.uint)
  if dtypes.is_int(dt) or dt == dtypes.bool: return least_upper_dtype(dt, dtypes.int)
  return least_upper_dtype(dt, to_dtype(getenv("SUM_DTYPE", "float32")))

Summing a million int8s in int8 would overflow, and summing halfs in half loses precision. So sum accumulates in at least u32 / i32 / f32, and then casts back for floats: Tensor([1., 2], dtype=half).sum() is f16, while int sums keep the wide type (int8.sum() is i32). can_lossless_cast answers "does dt1 hold every dt0 value?" using min/max and finfo. It is used by rewrite rules that remove redundant casts.

can_lossless_cast(i32, f32) = False: f32's 24-bit significand can't hold every 31-bit int. i16 → f32 is fine (15 ≤ 24).

3.11Emulating dtypes the hardware lacks

Not every backend has every dtype. Some GPUs have no bf16 or fp8 ALU, some lack 64-bit ints, and WebGPU has no f64. tinygrad's answer is a rewrite pass, do_dtype_decomps, run inside full_rewrite_to_sink as the "decomp dtypes" step (codegen/__init__.py:342):

tinygrad/codegen/decomp/dtype.py:198
def do_dtype_decomps(sink:UOp, ctx:DTypeDecompCtx) -> UOp:
  def _should_emulate(dt): return dt in EMULATED_DTYPES.tolist(dtypes) or dt not in ctx.renderer.supported_dtypes()
  for fr in sorted(filter(_should_emulate, ctx.dtypes)):
    to = dtypes.int if fr == dtypes.long else dtypes.float
    if DEBUG >= 2: print(f"emulating {fr} as {to}")
    pm = pm_float_decomp if fr in dtypes.floats else pm_long_decomp
    sink = graph_rewrite(sink, pm, name=f"decomp {fr} -> {to}", ctx=FloatDecompCtx(fr, to), bottom_up=True)
  • Floats (bf16, fp8, half): storage stays the same size but is typed as an unsigned int of that width. Every load is converted to float32 by bit-twiddling, the math runs in float32, and every store converts back with correct rounding (pm_float_decomp, dtype.py:167).
  • long / ulong: each 64-bit value becomes two 32-bit ints. Adds propagate a carry, multiplies are done schoolbook-style, shifts move bits across the halves (pm_long_decomp, dtype.py:143).
  • It triggers when the renderer's supported_dtypes() lacks the dtype, or when you force it with EMULATED_DTYPES=bfloat16,long (helpers.py:255), which is handy for testing a backend's emulation path on your laptop.

Read the four kernels top to bottom:

  1. Native bf16 uses the C type __bf16 and still converts through float for the multiply. The clang target used for this guide rejects __bf16, so this kernel can't compile here. That is exactly the situation emulation exists for.
  2. Emulated bf16 stores unsigned short. The load is val0 << 16 with special cases for subnormals and inf/NaN, and the store is a round-to-nearest-even with NaN handling. That is 20 lines of integer ops for one multiply, but it runs, and the last line shows the correct result [3.0, -4.5, 6.0].
  3. Native int64 x*3 + x was simplified by symbolic rewrites to x << 2 (Chapter 6).
  4. Emulated int64: the same shift on a pair of ints. The low half shifts, and its top 2 bits carry into the high half ((cast0>>1u)>>29u).

Chapter summary

  • DType(priority, bitsize, name, fmt) is frozen and interned. There are no pointer, image or vector dtypes any more: those are ops, shapes and AddrSpace.
  • Promotion: least_upper_dtype = min of the intersection of up-sets in promo_lattice, ordered by (priority, bitsize, name). Floats beat ints, i64+u64 has no int join, f16+bf16 → f32.
  • Python scalars are weak (weakint/weakfloat, bitsize 800). _broadcasted keeps a weak CONST weak, so it adopts its neighbour's dtype. Lists commit immediately (strong_dtype, commit_int).
  • Weakness ends at storage (commit_dtype, realize refuses weak) and in codegen (pm_commit_weak, pm_lower_weak, pm_cast_const), where every literal becomes a typed CAST(CONST).
  • DEFAULT_FLOAT/DEFAULT_INT are ContextVars read at call time.
  • dtype is derived: dtype_from_uop(op, src, arg). A CONST is weak or bool, CAST/BITCAST take their arg, ALU ops use promo_dtype.
  • cast converts values, bitcast reinterprets bits (and rescales the last axis). sum accumulates in ≥ 32 bits.
  • Unsupported dtypes are emulated by pm_float_decomp (bits in uintN, math in f32) and pm_long_decomp (pairs of int32), forced with EMULATED_DTYPES.
