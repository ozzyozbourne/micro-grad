CHAPTER 14Optimizations, tensor cores & BEAM

The AST from Chapter 13 says what to compute. This chapter is about how the work is shaped: which loops become GPU threads, which become vector lanes or unrolled code, which reductions are split across a workgroup. In this version of tinygrad all of it comes down to one operation, splitting a RANGE in two with shift_to. We look at that operation, then at the hand-written heuristic that picks splits, tensor cores, and BEAM search, which times real candidates. Everything shown is real output from this checkout.

14.1Intuition: same arithmetic, different loop shapes

A 16×16 matmul needs 16·16·16 multiply-adds however you arrange it. The arrangement still decides the speed:

  • GLOBAL: give each output element (or block of them) its own GPU work-item. The hardware runs the loop in parallel.
  • LOCAL: group work-items into a workgroup that shares fast on-chip memory and can synchronize.
  • UPCAST: unroll a loop completely inside one thread, so its iterations become independent registers or vector lanes (float4). On a reduce axis this is classic loop unrolling.
  • GROUP: split a reduction across the threads of a workgroup. Each thread reduces a slice, the partial results meet in local memory, and one more reduce finishes the job.
  • TC: hand a whole small matrix tile to a tensor-core instruction (WMMA).
Analogy: a kitchen GLOBAL is opening more kitchens. LOCAL is putting several cooks in one kitchen so they can pass ingredients over the counter (shared memory) and wait for each other (barrier). UPCAST is a cook chopping four carrots in one stroke. GROUP is several cooks each counting part of the stock, then adding up their tallies on the counter. The recipe (the AST) is the same in every case.
The key idea Every one of these is "split a RANGE of size \(n\) into two RANGEs of sizes \(n/k\) and \(k\), and give the new one an AxisType". A RANGE is a value, so the split is the substitution \(r \to r_{\text{outer}}\cdot k + r_{\text{inner}}\). It is applied to the AST with substitute. Later passes read the AxisTypes: the expander unrolls UPCAST ranges, gpudims turns GLOBAL/LOCAL into gidx/lidx, and fix_group_for_reduce builds local-memory reductions.

and apply_opts picks one of four strategies:

def apply_opts(ast:UOp, ren:Renderer, beam:int=0) -> UOp:
  if ast.arg is not None and ast.arg.optimized: return ast
  k = Scheduler(ast, ren)
  k.convert_loop_to_global()
  if ast.arg is not None and ast.arg.opts_to_apply is not None:
    for opt in ast.arg.opts_to_apply: k.apply_opt(opt)
  elif beam >= 1:
    from tinygrad.codegen.opt.search import beam_search
    rawbufs, var_vals = args_from_ast(ast, ren.target.device)
    # beam search may open devices
    with Context(ALLOW_DEVICE_USAGE=1):
      k = beam_search(k, rawbufs, var_vals, beam, bool(getenv("BEAM_ESTIMATE", 1)))
  elif not NOOPT and (ast.arg is None or ast.arg.applied_opts == ()):
    from tinygrad.codegen.opt.heuristic import hand_coded_optimizations
    # NOTE: hand_coded_optimizations doesn't support multiblock opts yet
    if not any(u.op is Ops.STAGE for u in ast.backward_slice):
      k = hand_coded_optimizations(k)
  return k.get_optimized_ast(name_override=ast.arg.name if ast.arg is not None and ast.arg.name != "test" else None)

Note the first thing it always does: convert_loop_to_global. If the renderer has_local (GPU-style), every non-reduce output range (the WEAK ranges ended by the top-level END) becomes GLOBAL. On the CPU (ClangRenderer.has_local = False) they stay WEAK and become plain loops. This is why the same AST starts as 16:WEAK 16:WEAK 16:WEAK on CPU and 16:GLOBAL 16:GLOBAL 16:WEAK on OpenCL.

How the BEAM env var gets there BEAM=n is read in compile_linear, which rewrites every kernel CALL with pm_beam to set KernelInfo.beam = n. The beam value is part of the AST, so it also changes ast.key and therefore the to_program cache key.

14.4The Scheduler and the axis-number trap

Opts are applied by Scheduler, a thin wrapper that holds the current AST and exposes it as a list of axes:

  @property
  def rngs(self):
    # Keep serial/vectorized reduction axes last, deriving their role from REDUCE rather than the axis type.
    # void RANGEs are loops, not opt axes. the DEVICE axis is launched, not an opt axis
    red = self.reduce_ranges
    return sorted([u for u in self.ast.backward_slice if u.op is Ops.RANGE and u.dtype is not dtypes.void and u.vmax > 0
                   and u.axis_type is not AxisType.DEVICE],
                  key=lambda x: (x in red and x.axis_type in (AxisType.WEAK, AxisType.UPCAST), x.arg))
  @property
  def full_shape(self): return [ssimplify(x.src[0]) for x in self.rngs]
  @property
  def axis_types(self) -> list[AxisType]: return [x.axis_type for x in self.rngs]

Opt.axis is an index into this list, as it is right now. After every opt the list is re-sorted: new UPCAST ranges sort after GLOBAL/WEAK ones (enum order), and serial reduce ranges always come last. So "axis 2" means different things before and after an opt. The example hit this: splitting axis 0 of a matmul by 4 makes the reduce axis move from index 2 to index 3. After one more UPCAST it is at index 4. The hand-written list in the example therefore reads (0, …), (1, …), (4, …).

A CPU matmul starts as [16:WEAK, 16:WEAK, 16:WEAK(reduce)]. You apply SPLIT(axis=0,(4,UPCAST)). What is axis 2 now?
rngs become [4:WEAK, 16:WEAK, 4:UPCAST, 16:WEAK(reduce)]. Axis 0 is the shrunk original, axis 1 the other output, axis 2 the new UPCAST, axis 3 the reduce. That is exactly the error the first draft of the example hit: "UPCAST is from (GLOBAL, LOCAL, WEAK), not UPCAST".

14.5shift_to: splitting one RANGE into two

Scheduler.shift_to, all of it:

  def shift_to(self, rng:UOp, amount:int, new_type:AxisType, top:bool=False, input_new_rng:UOp|None=None):
    check(rng.axis_type in split_targets[new_type], f"{new_type} is from {split_targets[new_type]}, not {rng.axis_type}")
    if (old_sz:=rng.src[0].divides(amount)) is None:
      raise KernelOptError(f"{amount} can't divide {rng.src[0]} in {self.colored_shape()}")
    new_rng = UOp.range(amount, next(self.opt_range), new_type, dtype=rng.dtype) if input_new_rng is None else input_new_rng
    replaced_rng = rng.replace(src=(old_sz,))
    sub_axis = (new_rng * old_sz + replaced_rng) if top else (replaced_rng * amount + new_rng)
    self.ast = self.ast.substitute({rng:sub_axis}, extra_pm=pm_flatten_range, name=f"shift {rng.axis_id} {amount} {new_type.name.lower()}")
    return replaced_rng, new_rng

Step by step:

  1. old_sz = n / amount (symbolically. divides returns None if it is not exact, and then the opt fails).
  2. The old range keeps its identity (same axis type and axis id) but gets the smaller bound: rng.replace(src=(old_sz,)).
  3. A brand-new range of size amount with a fresh axis id (opt_range counts up from the largest id in the AST) and the requested type.
  4. Every use of the old range is replaced by replaced*amount + new (new is the fast, inner part) or, with top=True, by new*old_sz + replaced (new is the slow, outer part).
  5. pm_flatten_range re-flattens the range lists of END/REDUCE, so END(…, r) becomes END(…, r_outer, r_new).

A GROUP is worth seeing in full. On a GPU-style renderer (OpenCL, rendered here without any device) the heuristic groups the reduce of a 4096-element sum by 16:

-- OpenCL source for the GROUPed sum (local memory + barrier):
__kernel void r_16_256(__global float* data0_1, __global float* data1_4096) {
  float buf0[1];
  float buf1[1];
  __attribute__ ((aligned (16))) __local float buf2[16];
  int lidx0 = get_local_id(0); /* 16 */
  *(buf0+0) = 0.0f;
  for (int Lidx0 = 0; Lidx0 < 256; Lidx0++) {
    float val0 = (*(data1_4096+((lidx0<<8)+Lidx0)));
    *(buf0+0) = ((*(buf0+0))+val0);
  }
  *(buf2+lidx0) = (*(buf0+0));
  barrier(CLK_LOCAL_MEM_FENCE);
  *(buf1+0) = 0.0f;
  for (int Lidx101 = 0; Lidx101 < 16; Lidx101++) {
    float val1 = (*(buf2+Lidx101));
    *(buf1+0) = ((*(buf1+0))+val1);
  }
  if ((lidx0==0)) {
    *(data0_1+0) = (*(buf1+0));
  }
}

Each of the 16 threads sums 256 elements into a register (buf0), writes its partial into __local float buf2[16], waits at the barrier (inserted by add_raw_barrier), sums the 16 partials (range Lidx101, whose id is the original +100 from fix_group_for_reduce), and only thread 0 stores. With top=True each thread reads a contiguous block ((lidx0<<8)+Lidx0).

14.9hand_coded_optimizations, decision by decision

heuristic.py is a fixed sequence of rules. Each rule calls k.apply_opt and catches KernelOptError:

linesrule
28–44Tensor cores first. If there is one reduce axis (or TC_OPT≥1), try Opt(TC, axis, (TC_SELECT, TC_OPT, USE_TC)) for axis 0,1,2 on a copy. On success, upcast/local the TC's M and N ranges and return.
50–58IMAGE only: upcast by 4 a unit-stride axis of an image buffer.
61–78Matvec. GPU, reduce of a MUL of two INDEXes, where the first index has the reduce range as a plain addend: GROUP the reduce by MV_THREADS_PER_ROW=8, LOCAL a global by MV_BLOCKSIZE=4, UPCAST it by MV_ROWS_PER_THREAD=4, and return.
81–89Grouping. If the product of upcastable (output) dims is ≤ 2048 (240 on QCOM), GROUPTOP the first reduce axis by 16. If that worked, stop.
94–109Masked axes. Fully upcast small (≤7) axes used in WHERE gates (pad/stack/cat patterns).
114–137More upcasts. While upcastable work ≥ 1024 and upcast size < 32: among axes that some buffer doesn't index (reuse!), upcast by 3 or 4 the one with the fewest/smallest strides.
141–150Unroll the reduce. If the last reduce dim is ≤ 32, upcast it fully (and a second one if both ≤ 3). Otherwise unroll by 4 if divisible.
153–154If nothing is upcast yet, upcast the last output axis by 4.
158–186Locals (GPU only). Rank global axes: "expand" axes (some buffer ignores them) first, then higher axis first. Give each a local size from [32 (axis 0 only), 16, 8, 4, 3, 2] with the total ≤ 128. Apply up to 3.

14.10Tensor cores

A tensor core computes \(D = A\cdot B + C\) for a small fixed tile (e.g. 8×8×8) cooperatively across a warp. Each lane holds a few elements of each fragment. TensorCore describes one instruction by its dtypes and, for A, B and C, which bits of the lane id and which bits of the per-lane element index map to which bits of the m/n/k tile coordinates. dims (N, M, K) and threads are derived from those bit lists:

How the TC opt is applied

_apply_tc_opt: the first REDUCE must be an ADD of a MUL (optionally CAST). For each candidate TensorCore with matching dtypes, it collects ranges only in in0, only in in1, and the reduce ranges. opt.axis picks one (N, M, K) triple from their product. Each axis is padded if needed (TC_OPT≥2), then split into 2s with shift_to, once per bit in axis_coords(). Lane bits (frag_c[0]) go into a single WARP range of size threads (input_new_rng=warp//2**i%2), and element bits become UPCAST ranges. 14.11BEAM search

The heuristic is a guess. BEAM measures. beam_search in outline:

  1. Cache. The key is {ast.key, amt, allow_test_size, device, suffix} in the sqlite diskcache table beam_search. On a hit, re-apply the stored opts and return. It is skipped with IGNORE_BEAM_CACHE=1 or CACHELEVEL=0.
  2. Actions. A fixed list of 209 Opts (search.py:14–22): UPCAST by {0,2,3,4,5,7} on axes 0–9, LOCAL by {0,2,3,4,8,13,16,29} on axes 0–7, GROUPTOP by {13,16,28,29,32,49,64,256}, one LOCAL 32, 10 TC variants, 10 SWAPs (+ PADTO with BEAM_PADTO). get_kernel_actions applies each to a copy of every beam member and drops failures and anything over BEAM_UPCAST_MAX=256 upcast or BEAM_LOCAL_MAX=1024 local.
  3. Compile every candidate (in the worker pool, PARALLEL = CPU count) with a timeout (BEAM_TIMEOUT_SEC=10) and a size limit (BEAM_UOPS_MAX=3000). Identical binaries are deduplicated (seen_libs), and candidates whose estimated ops exceed 1000× the smallest are skipped.
  4. Time each on the real device with _time_program: 3 runs, minimum taken, early stop if slower than 3× the current best. Huge global sizes are shrunk to ≤ 65536 and the time is scaled back up.
  5. Keep the best amt (BEAM=2 → 2) and repeat from step 2, until no candidate improves the best by at least BEAM_MIN_PROGRESS (0.01 µs).

14.12PADTO and SWAP

PADTO rounds a constant-size range up to a multiple (e.g. 17 → 32) so it can be split. It replaces the range, gates every INDEX that uses it with valid = r < 17 (the same Invalid mechanism as Chapter 13), and wraps reduce inputs in where(valid, x, identity). It refuses if padding would more than quadruple the work. TC padding with TC_OPT=2 uses it internally. SWAP exchanges the axis ids of two GLOBAL ranges. That changes their sort order and therefore which one becomes gidx0 vs gidx1, which can matter for coalescing and launch limits.

Chapter summary

  • Optimization runs inside full_rewrite_to_sink via apply_opts: opts_to_apply → BEAM → heuristic (unless NOOPT) → get_optimized_ast (name, applied_opts, optimized=True).
  • There are only four OptOps (TC, SPLIT, PADTO, SWAP). UPCAST/UNROLL/LOCAL/GROUP/GROUPTOP are all SPLIT(axis, (amount, AxisType, top)).
  • shift_to keeps the old RANGE (smaller bound) and substitutes old*k + new (or new*old_sz + old with top). Later passes act on the AxisTypes.
  • Opt.axis indexes the current, re-sorted Scheduler.rngs, where reduce axes come last.
  • The heuristic: TC → (image) → matvec → group small outputs → upcast masked → upcast for reuse → unroll the reduce → locals.
  • Tensor cores: TensorCore fragments as bit layouts; the TC opt splits M/N/K into WARP and UPCAST ranges and inserts a WMMA. Available on Metal, CUDA/PTX, AMD, and the PYTHON emulator.
  • BEAM: 209 actions, keep the best amt by real timing each round, cache the result on disk by AST key.
