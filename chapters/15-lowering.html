CHAPTER 15Lowering: expand, devectorize, decompose

After Chapter 14 a kernel is an optimized AST: a small DAG of RANGEs, INDEXes, a REDUCE, a STORE, with some ranges tagged UPCAST/LOCAL/GLOBAL. A C compiler cannot eat that. This chapter follows full_rewrite_to_sink through every one of its ~30 named graph_rewrite stages and shows, with real captured graphs, how the AST becomes a renderer-ready graph: vectors expanded and split into lanes, loads re-coalesced into float4s, reductions turned into accumulators, integer division turned into multiply+shift, exp2/sin turned into polynomials, hardware loops turned into gidx/lidx.

15.1Intuition: compiling for a specific kitchen

Think of the optimized AST as a recipe written by a chef who assumes an ideal kitchen: "for each of the 4 rows, sum the 8 values of the row — and do the 8 at once (UPCAST)". Lowering is the sous-chef who rewrites that recipe for the actual kitchen, one rule at a time: "we have no 8-wide adder, but we can load 4 floats at once; we have no exp2 instruction, so here is a polynomial; there is no division unit worth using, so multiply by a magic number and shift".

AnalogyThe renderer is the kitchen inventory. Every stage below looks at it: ren.code_for_op (which ALU ops can be printed directly), ren.supports_float4, ren.has_local, ren.global_max/local_max, ren.supported_dtypes(), ren.extra_matcher. The same AST lowers to different graphs for Clang and for OpenCL.

Mechanically, lowering is boring in the best way: full_rewrite_to_sink is a straight line of sink = graph_rewrite(sink, <PatternMatcher>, name="…") calls. Each one takes a SINK and returns a SINK. There is no other IR, no side tables: the input form and output form of every stage is a UOp graph (Chapter 4), and each stage is a PatternMatcher (Chapter 5).

The key ideaEach stage establishes an invariant the later ones rely on. After "expander": no UPCAST RANGE exists. After "remove reduces": no REDUCE exists. After "devectorize2": every ALU op is scalar. After "lower all index dtypes": no weakint index math remains. After "late decompositions": every ALU op is in ren.code_for_op. After "range to special": only loop RANGEs remain. The final type_verify(sink, spec_program) checks the end state.

def full_rewrite_to_sink(ast:UOp, ren:Renderer, optimize:bool=True) -> UOp:
  if DEBUG >= 5: print(render_uir(ast))
  if SPEC: type_verify(ast, spec_tensor)

  # resolve UNSHARDs (multi-device UNSHARDs are already resolved by the scheduler; this handles in-kernel shards, e.g. fragments)
  sink = graph_rewrite(ast, multi_pm, name="multi_pm")

  # preprocess
  sink = graph_rewrite(sink, pm_mops, name="early movement ops", bottom_up=True)

  # first we optimize
  if optimize:
    # collapse loads reduce (indexing by a tensor)
    sink = graph_rewrite(sink, pm_load_collapse, name="load collapse")

    # split ranges
    sink = graph_rewrite(sink, pm_split_ranges+pm_flatten_range, init_ctx=MapCtx, name="split ranges")

    # symbolic (NOTE: this is a requirement for pm_simplify_ranges to be correct)
    sink = graph_rewrite(sink, sym+pm_flatten_range, name="initial symbolic")

    # optimize (schedule) the AST
    sink = graph_rewrite(sink, pm_flatten_range+pm_simplify_ranges, init_ctx=MapCtx, name="simplify ranges")

    # do postrange optimization, BEAM or hand_coded_optimizations
    sink = apply_opts(sink, ren, beam=ast.arg.beam)

  # ** expander (expand_rewrite) **
  # reduce_unparented: a REDUCE whose src folded to a CONST (e.g. x*0) has no parented ranges, collapse it before the expander
  sink = graph_rewrite(sink, sym+pm_move_where_on_load+pm_flatten_range+pm_reduce_unparented, name="postopt symbolic")

  # expand
  sink = graph_rewrite(sink, expander, ctx=build_range_map(sink), name="expander")

  slots = itertools.count(max([u.arg.slot+1 for u in sink.toposort() if u.op in {Ops.BUFFER, Ops.ALLOC}], default=0))

  # remove reduce
  sink = graph_rewrite(sink, mop_cleanup+pm_reduce_local, ctx=slots, name="remove reduces")

  # add locals
  sink = graph_rewrite(sink, pm_add_local_buffers, ctx=slots, name="add local buffers")

  # group GPU dimensions early so their index arithmetic goes through normal lowering
  sink = graph_rewrite(sink, pm_group_gpudims, ctx=ren, name="group gpudims", walk=True)

  # **** optimizations are done, now we lower to actual code ****

  sink = graph_rewrite(sink, symbolic_simple+pm_expand_broadcast+pm_add_loads, name="*** expand broadcast / add loads")

  # devectorize
  sink = graph_rewrite(sink, symbolic_simple+devectorizer2+indexing_simplify, name="devectorize2")

  # some coalescing misses without this
  sink = graph_rewrite(sink, sym, name="early symbolic")

  # do memory coalescing (late)
  sink = memory_coalescing(sink, ren)
  # an image is read_only or write_only, so a PARAM that is both loaded and stored stays a buffer
  loaded, stored = [{u.src[0].buf_uop for u in sink.toposort() if u.op is op} for op in (Ops.LOAD, Ops.STORE)]
  sink = graph_rewrite(sink, pm_simplify_add_image, name="add images", ctx=({}, ren, loaded & stored), bottom_up=True)

  # extra symbolic before decomp. crashes without this?
  # NOTE: also run indexing_simplify here, while the index is still weakint and (x+y)*c -> x*c+y*c applies
  # commit widths minted in this fixpoint before lowering inspects INDEX shapes
  sink = graph_rewrite(sink, sym+indexing_simplify+pm_commit_weak, name="extra symbolic")

  # the boundary: required compute dtypes settle here; derivable const edges may stay bare
  # NOTE: we need indexing_simplify to remove the cast to long using the Invalid
  # NOTE: symbolic must NOT be composed here -- pm_data_invalid pushes the weak result CAST into a gated WHERE, remaking the weak node, and it cycles
  sink = graph_rewrite(sink, pm_lower_weak+indexing_simplify, name="lower all index dtypes")

  # final symbolic before decomp
  sink = graph_rewrite(sink, symbolic, name="final symbolic")

  sink = graph_rewrite(sink, pm_cast_float_alu, name="cast float alu operands")

  # **** decomps ****

  # floordiv+mod / dtype decomp (early)
  supported_ops = tuple(ren.code_for_op.keys())
  pm_decomp = symbolic_simple+get_simplifying_rewrite_patterns(supported_ops)
  sink = graph_rewrite(sink, pm_decomp, name="early decompositions")

  # late decomps + move gates from unrenderable INVALID where
  pm_decomp = pm_decomp+\
    get_late_rewrite_patterns(supported_ops, bool(DISABLE_FAST_IDIV))+\
    get_transcendental_patterns(supported_ops, TRANSCENDENTAL>=2)
  sink = graph_rewrite(sink, pm_decomp, ctx=ren, name="late decompositions")
  # Transcendental decompositions can introduce unsupported dtypes, e.g. uint64 in Payne-Hanek reduction.
  sink = graph_rewrite(sink, pm_dtype_decomps+pm_commit_weak, ctx=DTypeDecompCtx(ren), name="decomp dtypes")
  sink = graph_rewrite(sink, pm_move_gates_from_index, name="move gates from index")

  # final rules for the renderer (without sym)
  extra_matcher = ren.extra_matcher if ren.extra_matcher is not None else PatternMatcher([])
  pm_final_rewrite = pm_commit_weak+pm_decomp+extra_matcher+pm_split_ends
  sink = graph_rewrite(sink, pm_final_rewrite+pm_remove_invalid, ctx=ren, name="final rewrite")

  # commit every const still bare so no renderer reads one
  sink = graph_rewrite(sink, pm_cast_const, name="cast consts", walk=True)

  # add implicit barriers (stores/loads through LOCAL memory ordered by AFTER or across loop iterations need workgroup barriers)
  sink = graph_rewrite(sink, pm_implicit_barriers, name="add implicit barriers")

  # hardware ranges are no longer loops; preserve their already lowered bounds
  sink = graph_rewrite(sink, pm_range_to_special, name="range to special")

  # this was the linearizer
  sink = graph_rewrite(sink, pm_add_control_flow, ctx=CFGContext(sink), name="add control flow", bottom_up=True)

  # put the variables in slots
  num_params = max([x.arg.slot + 1 for x in sink.toposort() if x.op is Ops.PARAM and x.arg.slot != -1], default=0)
  sink = graph_rewrite(sink, pm_number_params, ctx=(num_params, {}), name="number variables", walk=True)

  if VIZ: graph_rewrite(sink, PatternMatcher([]), name="View Output AST")
  if SPEC:
    import os
    if os.environ.get("DBGTV"):
      try: type_verify(sink, spec_program)
      except RuntimeError:
        print(render_uir(sink))
        raise
    else: type_verify(sink, spec_program)

  # return the rewritten sink
  return sink

15.4Phase A: preprocess, simplify ranges, optimize

These stages belong to the optimizer (Chapter 14), but two of them are pure range algebra from codegen/simplify.py and set the stage for everything else:

  • split ranges (pm_split_ranges): if a RANGE r of constant length appears as r % c with c dividing the length, it is replaced by two ranges r0*c + r1 (axis ids get an extra 0/1). The mod disappears.
  • simplify ranges (simplify_merge_adjacent): tries to merge two adjacent ranges of the same type into one of length s0*s1, substituting r0 → r//s1, r1 → r%s1, and keeps the merge only if the number of DIV/MOD in the result does not grow. It also shrinks ranges guarded by r < c (mark_gated).

15.5The expander: UPCAST ranges become vectors

An UPCAST range means "don't loop over me — do all my iterations at once, in registers". The expander implements that literally: it replaces the RANGE by a constant vector of its values, with a shape. A UOp with a shape is a little tensor (Chapter 4): ALU ops on shaped UOps broadcast like numpy.

  ctx: dict[tuple, int] = {}
  for x in sink.toposort():
    if x.op is Ops.RANGE and x.axis_type is AxisType.UPCAST:
      ctx[x.arg] = len(ctx)
  return ctx

def expand_reduce(r:UOp):
  range_srcs = []
  new_axes = []
  for u in r.src[1:]:
    if u.op == Ops.RANGE:
      range_srcs.append(u)
    else:
      for i,s in enumerate(u.shape):
        if s > 1: new_axes.append(i)
  if len(new_axes) == 0: return None
  assert r.arg[1] == 0
  # permute so new_axes come to front, then reduce
  perm = tuple(new_axes) + tuple(i for i in range(len(r.src[0].shape)) if i not in new_axes)
  out_shape = tuple([1 if i in new_axes else s for i,s in enumerate(r.src[0].shape)])
  return r.src[0].permute(perm).reduce(*range_srcs, arg=(r.arg[0], len(new_axes))).reshape(out_shape)

15.6Locals and GPU dimensions

add local buffers (add_local_buffer) turns each STAGE into a real ALLOC in LOCAL (or REG) address space, a store of the staged value into it inside its ranges, and an INDEX to read it back.

group gpudims (group_gpudims) runs once on the SINK. It collects GLOBAL ranges and LOCAL/WARP ranges, and asks get_grouped_dims to fit them into the renderer's limits (global_max, local_max, at most 3 dims each): too many dims → merge neighbours (_group_dims), a dim too big → split by its smallest factor into the next dim (_split_dims). The new ranges keep their hardware dimension as axis id; the old ranges are substituted by flat // prod(dims[i+1:]) % dims[i] expressions over them. Global dims are assigned in reverse (the last, fastest-moving axis gets gidx0). It also masks global stores that don't depend on some local range so only lidx==0 writes (you'll see cmpeq %15, 0 gating the final store of sum·GPU below).

def _group_dims(dims:tuple[sint, ...], max_sizes:tuple[int, ...]):
  while len(dims) > len(max_sizes) or any(_dim_max(d) > m for d,m in zip(dims, max_sizes)):
    for i,m in enumerate(max_sizes):
      if i < (len(dims)-1) and _dim_max(dims[i]) * _dim_max(dims[i+1]) <= m:
        dims = dims[:i] + (dims[i]*dims[i+1],) + dims[i+2:]
        break
    else: return None
  return dims

def _split_dims(dims, max_sizes):
  if all(d <= m for d,m in zip(dims, max_sizes)): return dims
  _dims = list(dims) + [1]*(3-len(dims))
  for i in range(len(_dims)):
    while _dims[i] > max_sizes[i]:
      div = next((d for d in range(2, math.ceil(math.sqrt(_dims[i])) + 1) if (_dims[i] % d) == 0), 1)
      if div == 1: raise RuntimeError(f"cannot limit dim {dims=}, {max_sizes=}")
      _dims[i], _dims[(i+1)%len(_dims)] = _dims[i]//div, _dims[(i+1)%len(_dims)]*div
  return tuple(_dims[:2] if _dims[2] == 1 else _dims)

  else:

    limited = grouped if (grouped := _group_dims(dims, max_sizes)) else dims

  # Keep hardware axes as ranges through index lowering. The axis id is the hardware dimension.

  flat = sum(idx * math.prod(limited[i+1:]) for i,idx in enumerate(raw_idxs))
  return [ssimplify(flat // math.prod(dims[i+1:])) if i == 0 else ssimplify((flat // math.prod(dims[i+1:])) % dims[i]) for i in range(len(dims))]

15.8Memory coalescing and images

memory_coalescing is a plain function, not a PatternMatcher. def magicgu(vmax:int, d:int) -> tuple[int,int]:
  # calculate m,s such that x//d == (x*m) >> s for all 0 <= x <= vmax, d>0; adapted from Hacker's Delight, Chapter 10
  nc = (vmax+1)//(d) * d - 1
  nbits = vmax.bit_length()
  for s in range(0, 2*nbits + 1):
    if 2**s > nc*(d - 1 - (2**s - 1) % d):
      m = (2**s + d - 1 - (2**s - 1) % d)//d
      return m, s

def fast_idiv(ren: Renderer, x: UOp, d: int, dont_cast=False) -> UOp|None:
  if d <= 0 or x.vmin < 0: return None
  if (vmax:=min(x.vmax, x.dtype.max)) < d: return x.const_like(0)
  m,s = magicgu(vmax, d)
  if m*vmax <= x.dtype.max: return (x*m) >> s
  # before we try casting to a larger dtype (slow), we see if there are powers of two in d we can shift to make x smaller
  if (k := (d & -d).bit_length()-1) > 0:
    if (ret:=fast_idiv(ren, x >> k, d >> k, dont_cast=True)) is not None: return ret
  if dont_cast: return None
  # the next integer width that holds x*m
  widen = {dtypes.int8:dtypes.int16, dtypes.int16:dtypes.int32, dtypes.int32:dtypes.int64, dtypes.int64:dtypes.uint64,
           dtypes.uint8:dtypes.uint16, dtypes.uint16:dtypes.uint32, dtypes.uint32:dtypes.uint64}
  if (next_dtype := widen.get(x.dtype)) is not None and next_dtype in ren.supported_dtypes():
    if m*vmax <= next_dtype.max: return ((x.cast(next_dtype)*m) >> s).cast(x.dtype)
  return None

15.11Decompositions II: exp2, log2 and sin as polynomials

If the renderer can't print EXP2/LOG2/SIN (or TRANSCENDENTAL=2 forces it), get_transcendental_patterns replaces them with SLEEF-style 1-ULP algorithms built from adds, multiplies, compares and bit tricks (float16/bfloat16 inputs are computed in float32). Every approximation has the same three-step shape:

  1. Range reduction: write the input as an integer part and a small remainder. exp2: \(x = q + s\) with \(q=\mathrm{round}(x)\), \(s\in[-\tfrac12,\tfrac12]\). sin: \(x = q\cdot\tfrac{\pi}{2}\ \text{or}\ q\pi + r\) with small \(r\).
  2. Polynomial on the small interval, evaluated with Horner's rule (helpers.polyN: reduce(lambda acc,c: acc*x+c, p, 0.0)).
  3. Reconstruction: exp2: \(2^x = 2^s\cdot 2^q\), where \(2^q\) is built by writing \(q+127\) into the exponent bits (pow2if) — in two halves (ldexp2k) so \(2^q\) never overflows on its own. sin: flip the sign by quadrant bits q&1, q&2.

def xexp2(d:UOp) -> UOp:
  """
  Implements a 1.0 ULP approximation for Ops.EXP2

For sin, small angles (|x| < 30) use Cody–Waite reduction: \(r = x - q\pi\) computed with \(\pi\) split into four float32 pieces 3.1414794921875 + 0.000113159… + 1.98e-9 + 1.2e-10, so that \(q\cdot\pi_A\) is exact and the cancellation against \(x\) loses nothing. Large angles use Payne–Hanek: multiply the mantissa by 96 bits of \(2/\pi\) taken from a 190-bit table, in 64-bit integer arithmetic, and read the quadrant from the top two bits. That's where the uint64 UOps in a sin kernel come from (and why "decomp dtypes" runs after this stage — on a renderer without int64 they'd be emulated next).

def cody_waite_reduction(d:UOp) -> tuple[UOp, UOp]:
  """
  Performs Cody-Waite Reduction: computes the reminder of `d` modulo pi/2 for the values `d` where
      0 <= abs(d) <= 39800.0
  Returns a tuple of `(r, q)`, where the output format is the same as that of `payne_hanek_reduction`.
  """
  def _reduce_d(x:UOp, q:UOp):
    # https://github.com/shibatch/sleef/blob/4e08851f59fc2b545f9c393c6a23dfd311a26308/src/libm/sleefdp.c#L789-L823
    if x.dtype == dtypes.float64:
      # https://github.com/shibatch/sleef/blob/f6d8a841fbfddd26ce712834d4da220cd76048fb/src/common/misc.h#L77
      PI_A, PI_B, PI_C, PI_D = 3.1415926218032836914, 3.1786509424591713469e-08, 1.2246467864107188502e-16, 1.2736634327021899816e-24
      d = qdh * -PI_A + x
      d = q * -PI_A + d
      d = qdh * -PI_B + d
      d = q * -PI_B + d
      d = qdh * -PI_C + d
      d = q * -PI_C + d
      d = (qdh + q) * -PI_D + d
    elif x.dtype == dtypes.float16:

      d = _reduce_d(x.cast(dtypes.float32), q.cast(dtypes.float32)).cast(dtypes.float16)

      d = q * -3.1414794921875 + x
      d = q * -0.00011315941810607910156 + d
      d = q * -1.9841872589410058936e-09 + d
      d = q * -1.2154201256553420762e-10 + d
    return d

def xsin(d:UOp, fast:bool=False, switch_over:float=30.0) -> UOp:
  """
  Implements a 1.0 ULP approximation for Ops.SIN.
  - fast=True assumes x <= switch_over.
  - switch_over is the threshold for switching to payne_hanek_reduction.
  """
  assert d.dtype in TRANSCENDENTAL_DTYPES
  # mask +-inf/nan as zero
  x = _lazy_map_numbers(d, d.const_like(0.0), d.const_like(0.0), d.const_like(0.0), d)
  # x_sign = sign(x)
  x_sign = x.ne(0).where((x<0).where(x.const_like(-1), x.const_like(1)), x.const_like(0))
  x_abs = x * x_sign
  r, q = (cody_waite_reduction if fast else payne_hanek_reduction)(x_abs)
  if fast: result = sin_poly_small(r, q)
  else:
    # Payne Hanek Reduction assumes abs(x) >= pi/4, so for smaller values, use cody_waite_reduction.
    r_small, q_small = cody_waite_reduction(x_abs)
    result = (x_abs<switch_over).where(sin_poly_small(r_small, q_small), sin_poly_large(r, q))
  # adjusts the sign for abs(x)
  result = result * x_sign
  # sin(Inf) = NaN, sin(-Inf) = NaN, sin(NaN) = NaN
  return _lazy_map_numbers(d, d.const_like(math.nan), d.const_like(math.nan), d.const_like(math.nan), result)

  • …the Cody–Waite order is not preserved in C. 15.13The tail: gates, renderer quirks, barriers, SPECIAL, control flow

  • move gates from index (gater.py): until now, out-of-bounds access was expressed as an index value valid.where(idx, Invalid). Renderers want a gated LOAD (LOAD(idx, alt=0, gate) → gate ? *p : 0) or gated STORE instead; a WHERE right after a gated load becomes the load's alternative value.
  • final rewrite: pm_decomp again, plus the renderer's own extra_matcher (e.g. Clang routes double→half through float, narrows uint8 math, emulates bf16 casts), plus pm_split_ends (an END closing several ranges becomes nested single-range ENDs, innermost first), plus pm_remove_invalid.
  • add implicit barriers (add_raw_barrier, add_war_barrier): an AFTER on a LOCAL buffer whose dependencies contain a LOCAL store gets a BARRIER (read-after-write); a loop that both stores and loads the same LOCAL buffer gets a barrier at the end of its body (write-after-read).
  • range to special (pm_range_to_special): GLOBAL/LOCAL RANGEs are not loops — the hardware runs one instance per index — so they become SPECIAL("gidx0")/SPECIAL("lidx0"), and pm_split_ends drops them from ENDs.
  • add control flow: CFGContext computes which sibling loops must come before which and records it as AFTER edges on RANGE bounds — the subject of Chapter 16.
  • number variables: symbolic-shape variables (PARAMs with slot=-1) get slots after the buffers.
  • spec check: with SPEC=1 (the default, helpers.py:277), type_verify(sink, spec_program) (spec.py:204) rejects movement ops, Invalid, bare CONSTs, weak dtypes, non-int32 SPECIALs….

15.14Hammer it again: one AST, two kitchens

Same question, other angle: how much of lowering is "the kernel" and how much is "the renderer"? Take the 16×16 add. On OpenCL (has_local, float4) the explorer's add·GPU shows GLOBAL/LOCAL ranges, gpudims, SPECIALs, and float4 SHRINKs. On Clang the very same AST gets has_local = False (so convert_loop_to_global returns early: no GLOBAL ranges ever exist), global_max=(1,0,0), and a loop. And for exp: on OpenCL "late decompositions" is nearly a no-op; on Clang it is the biggest stage of all (14 → 78 UOps in the explorer's exp·CPU, one EXP2 UOp becoming the whole xexp2 algorithm), and on a renderer without int64 a sin would grow again in "decomp dtypes" (Payne–Hanek's uint64 math).

What breaks if you reorder?Each stage's comment hints at a dependency: "symbolic (NOTE: this is a requirement for pm_simplify_ranges to be correct)", "some coalescing misses without this", "extra symbolic before decomp. crashes without this?", "symbolic must NOT be composed here — … it cycles". Move "memory_coalescing" before "devectorize2" and it finds no scalar loads to group; move "late decompositions" before "lower all index dtypes" and fast_idiv has no dtype maximum; move "range to special" before "group gpudims" and the hardware dims are wrong; skip "cast consts" and spec_program fails on the first bare CONST.
You add a new renderer whose language has no % operator but has &. Where does x % 8 get handled, and where does x % 7?
get_simplifying_rewrite_patterns adds x % 2^k → x & (2^k-1) when AND is in code_for_op. A non-power-of-two modulus falls through to floormod_to_mod (TRUNCMOD + sign fix); only get_late_rewrite_patterns with fast idiv enabled can remove it, and only for non-negative x with a divisor whose magic multiply fits.
Why do the loads appear (pm_add_loads) only at stage 12, so late?
Keeping "address" and "value" fused in INDEX keeps the graph small and the early rewrites simple; once the structure is final, every value use of an INDEX into real memory gets an explicit LOAD, ready for devectorizing and coalescing.

Chapter summary

  • full_rewrite_to_sink(ast, ren) is ~30 named graph_rewrite calls, SINK in, SINK out; the renderer is a parameter of almost every one (code_for_op, supports_float4, has_local, global/local_max, supported_dtypes, extra_matcher).
  • expander: UPCAST RANGE → constant vector with a shape; REDUCE gains horizontal axes. remove reduces: horizontal reduce → ALU chain; loop reduce → REG accumulator with AFTER/STORE/END; grouped reduce → LOCAL STAGE.
  • add loads → devectorize2 → memory_coalescing: make every op scalar, simplify each lane's index, then rebuild aligned SHRINK(buf, i, 4) vector loads/stores.
  • weak → concrete dtypes before decompositions; cast consts after them.
  • decompositions are generated from code_for_op: DIV/MOD → shifts/masks/TRUNCDIV (+ fast idiv (x*m)>>s when DISABLE_FAST_IDIV=0), MAX → WHERE, MUL → SHL, EXP2/LOG2/SIN → range reduction + polynomial + reconstruction; unsupported dtypes are emulated.
  • tail: gates move into LOAD/STORE, barriers are inserted for LOCAL memory, GLOBAL/LOCAL ranges become SPECIAL, sibling loops get ordering edges, and spec_program verifies the result.
