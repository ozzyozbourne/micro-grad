CHAPTER 04UOp: the one IR

Every stage of tinygrad, from a + b on a Tensor to a line of generated C or an AMD instruction, is a graph of one Python class: UOp. This chapter takes that class apart: its three fields, the hash-consing that makes equal graphs the same object, the derived properties (dtype, shape, key, vmin/vmax), all 75 members of the Ops enum, and the same computation shown as a real tensor graph, a real kernel AST, and a real linearized program.

4.1Intuition: one kind of brick

Most compilers have several intermediate representations, each with its own classes: an AST, a high-level graph IR, a low-level SSA IR, machine instructions. Every boundary between two IRs needs a translator and a printer, and the optimization machinery gets written once per IR. tinygrad has one IR. A tensor expression, a scheduled kernel, a list of loads and stores ready to print as C, and the schedule itself (a list of kernel calls) are all trees of the same object:

opan Ops enum member
what this node is: ADD, RESHAPE, RANGE, STORE, SINK…
srca tuple of UOps
the inputs; this is what makes it a DAG
argany hashable Python value
op-specific payload: a constant, a DType, a ParamArg, an axis tuple…
Analogy: LEGO with one brick shape Every brick has the same studs (op/src/arg), so every tool works on every model: the pattern matcher (Chapter 5), the printer, toposort, VIZ, caching by key. What changes from stage to stage is which ops appear. The tensor graph uses RESHAPE and PERMUTE. The kernel AST has none of those, but has RANGE and INDEX. The final program has LOAD, STORE and casts to int. Compiling means repeatedly swapping one vocabulary of bricks for another by graph rewriting.

② kernel AST

③ linear program

After codegen (Ch 15–16). A flat, ordered list of UOps (a LINEAR) with explicit LOAD/STORE, accumulators and int casts. It prints straight to C.

4.2Anatomy of the class

The definition is short. Only op, src and arg are stored; every other attribute is computed from them on demand and cached in the instance __dict__. Source: class UOp.

tinygrad/uop/ops.py:226–243
# NOTE: this should be frozen, but frozen is slower
@dataclass(eq=False, slots=True)
class UOp(RandMixin, metaclass=UOpMetaClass):
  op:Ops
  src:tuple[UOp, ...] = tuple()
  arg:Any = None
  @recursive_property
  def dtype(self) -> DType: return dtype_from_uop(self.op, self.src, self.arg)
  def __del__(self):
    # NOTE: getattr because this object may be partially constructed (e.g. if __init__ raised, like the BEAM timeout SIGALRM)
    try: del UOpMetaClass.ucache[(self.op, self.src, self.arg, type(self.arg))]
    except (AttributeError, KeyError): pass
  def __reduce__(self): return UOp, (self.op, self.src, self.arg)
  def replace(self, **kwargs) -> UOp:
    new_args = (kwargs.pop("op", self.op), kwargs.pop("src", self.src), kwargs.pop("arg", self.arg))
    assert len(kwargs) == 0, f"unused kwargs in replace {list(kwargs)}"
    if (self.op, self.src, self.arg) == new_args: return self
    return UOp(*new_args)

Note what is not a field: dtype. It is a recursive_property computed by the total function dtype_from_uop, one big match over every op: STORE/SINK/LINEAR/… are void; comparisons are bool; CAST/BITCAST take their arg; CONST derives the dtype from the Python type of its value (int → weakint, float → weakfloat, bool → bool; Chapter 3); binary ops promote their sources; LOAD, REDUCE, RANGE and AFTER pass through src[0].dtype.

tinygrad/uop/ops.py:115–137 — the first rules of dtype_from_uop
def dtype_from_uop(op:Ops, src:tuple[UOp,...], arg:Any) -> DType:
  # here are the dtype production rules, total over all Ops
  match op:
    case Ops.STORE | Ops.LINEAR | Ops.SINK | Ops.PROGRAM | Ops.SOURCE | \
         Ops.BACKEDGE | Ops.BARRIER | Ops.IF | Ops.ENDIF | Ops.NOOP | \
         Ops.REWRITE_ERROR | Ops.PYLITERAL:
      # always void
      return dtypes.void
    case Ops.CALL:
      # a call has the dtype of its body, void for opaque bodies
      return src[0].dtype
    case Ops.CUSTOM_FUNCTION:
      # an external function states its return dtype in the arg
      return arg.dtype
    case Ops.CUSTOM | Ops.CUSTOMI:
      assert isinstance(arg, tuple) and len(arg) == 2 and isinstance(arg[1], DType), f"CUSTOM/CUSTOMI arg must be (str, DType), got {arg}"
      return arg[1]
    case Ops.INS:
      # arg is (instruction, dtype, *registers), a queue command or an asm line is void
      assert isinstance(arg, tuple) and len(arg) >= 2 and isinstance(arg[1], DType), f"INS arg must be (instruction, DType, *registers), got {arg}"
      return arg[1]
    case Ops.INDEX:
      # an image access is always float, no matter the storage dtype
Deep dive: why recursive_property and not functools.cached_property?

A property like dtype of a node depends on the same property of its sources. With cached_property, evaluating it on the root of a 100k-node chain recurses 100k Python frames deep, which raises RecursionError. recursive_property (ops.py:206) instead walks the graph with the iterative toposort, gated to visit only nodes that don't have the value cached yet, and fills it in from the leaves up. So the recursion in the definition never becomes recursion on the Python stack. dtype, key, _shape, device, _ranges and addrspace are all defined this way.

class recursive_property:
  def __init__(self, fxn):
    self.fxn = fxn
    self.nm = fxn.__name__
    self.__doc__ = fxn.__doc__
  def __get__(self, x:UOp|None, owner=None):
    if x is None: return self
    for node in x.toposort(gate=lambda node: self.nm not in node.__dict__, enter_calls=True): node.__dict__[self.nm] = self.fxn(node)
    return x.__dict__[self.nm]

4.3Hash-consing: equal means identical

UOps are hash-consed, also called interned: building a UOp with an (op, src, arg) triple that already exists returns the existing object. The mechanism is a metaclass whose __call__ runs before the dataclass __init__ and checks a global cache first:

tinygrad/uop/ops.py:190–204 — UOpMetaClass
class UOpMetaClass(type):
  ucache:dict[tuple, weakref.ReferenceType[UOp]] = {}
  def __call__(cls, op:Ops, src:tuple[UOp,...]=tuple(), arg:Any=None):
    # NOTE: the key must separate nodes of different dtype: a CONST's dtype is the type of its arg, and True == 1 as dict keys
    if (wret:=UOpMetaClass.ucache.get(key:=(op, src, arg, type(arg)), None)) is not None and (ret:=wret()) is not None: return ret
    UOpMetaClass.ucache[key] = weakref.ref(created:=super().__call__(op, src, arg))
    if SPEC > 1:
      from tinygrad.uop.spec import spec_full
      if SPEC > 2:
        # SPEC=3 checks the shape
        _ = created._shape
      with Context(CHECK_OOB=0): fret = cast(bool|None, spec_full.rewrite(created))
      if fret is not True: raise RuntimeError(f"SPEC ISSUE {fret}: {created}")
    return created

Three details are worth reading closely:

  • The key is (op, src, arg, type(arg)). Since src is a tuple of already-interned UOps, hashing it hashes object identities, so building a node costs O(#src) and never walks the whole subgraph. type(arg) is included because 1 == 1.0 == True in Python, but those are three different constants (weakint, weakfloat, bool).
  • The cache holds weakrefs. It doesn't keep nodes alive. If the weakref is dead, the node is simply rebuilt.
  • SPEC>1 type-checks every newly created node against spec_full (a PatternMatcher, Chapter 5). Because every node is created exactly once, that check also runs exactly once per node.
=== 3. hash-consing: same (op, src, arg) -> the SAME Python object ===
a is b: True   id(a)==id(b): True
UOp.const(1) is UOp.const(1):    True
UOp.const(1) is UOp.const(True): False  (type(arg) is part of the cache key)
UOp.const(1) is UOp.const(1.0):  False

=== 4. the cache holds WEAK references: nodes vanish when nobody uses them ===
new cache entries after building q*7+3: 5
after `del` + gc:                        0 (UOp.__del__ removed them)

When the last strong reference dies, UOp.__del__ removes the cache entry (ops.py:234). Only 5 entries appeared for q*7+3 although it has 6 nodes, because the empty STACK under every Variable already existed: it is shared.

What hash-consing buys
  1. Equality is identity. a is b is an O(1) structural-equality test. Pattern rules such as x//x → 1 can check "both sources are the same expression" with is.
  2. Common subexpression elimination is free. (x+y)*(x+y) contains one ADD node with two edges to the MUL.
  3. UOps are cheap, safe dict keys. Every graph pass keeps dict[UOp, …] memo tables (the rewrite engine's replace dict, the kernel cache, tensor_maps).
  4. Immutability is forced. You can't mutate a shared node without corrupting every graph that contains it, so you never mutate: you replace (4.7).

4.4key: a content hash that survives processes

Identity works within one process. To cache compiled kernels on disk, or to compare graphs across runs (process replay), you need a stable name for a graph's content. That is key, a sha256 over (op, dtype, arg) plus the keys of the sources, computed bottom-up (it is a recursive_property too):

  def is_invalid(self) -> bool: return self.op is Ops.CONST and self.val is Invalid
  @recursive_property
  def key(self) -> bytes:
    return hashlib.sha256(str((self.op, self.dtype, self.arg)).encode() + b"".join([s.key for s in self.src])).digest()
=== 5. key: a sha256 content hash, stable across processes ===
a.key = 16fb0beebcbf6cfc2d46853976ab577b0598f044caa604179219b9d6c9a6c148
same expression, same key: True | different expression: False

Where it is used: to_program_key starts with ast.key. That is the compiled-program cache: two identical kernel ASTs, whether from different Tensors or different runs, compile once. to_elf and the schedule cache use it as well.

4.5The Ops enum: the vocabulary

class Ops has 75 members, grouped into seven commented sections. It is a FastEnum, an IntEnum whose auto() values are unique across subclasses. The first comment in the class is a design statement:

# the order of these Ops controls the order of the toposort
class Ops(FastEnum):
  # ** 1 -- defines/special **

  # this is a RANGE for GPU dimensions, similar to symbolic shapes but not exactly
  SPECIAL = auto()

  # BUFFER references bound storage; ALLOC declares unbound global storage
  BUFFER = auto(); ALLOC = auto()

The order is semantic: low numbers are "defines" (SPECIAL, BUFFER, PARAM), then structure (CALL, PROGRAM, SINK, AFTER), then memory (INDEX, LOAD, STORE), math, control flow and CONST, and finally the ops that only exist in the tensor graph (movement, COPY, REDUCE). In this version the order shows up through tuplize, a sort key that starts with op.value:

  @functools.cached_property
  def tuplize(self) -> _UOpTuple:
    # arg goes through repr: args of different types (None, str, tuple) must stay mutually comparable for the sort
    return _UOpTuple((self.op.value, repr(self.arg), self.dtype,)+tuple([x.tuplize for x in self.src]))

tuplize is the tie-breaker in the linearizer's priority sort (linearizer.py:36, on by default via TUPLE_ORDER=1) and the canonical order for commutative index math (symbolic.py:237, which flips a+b so the smaller tuplize comes first). Since Ops.CONST (57) sorts after PARAM (6) and RANGE (52), constants always end up on the right: 2*x becomes x*2. Many pattern rules rely on that and only match x*c, never c*x.

=== 9. Ops enum order is semantic: tuplize puts CONSTs last ===
Ops.PARAM = 6  Ops.ADD = 30  Ops.CONST = 57
2*x as built: (2*x) -> after symbolic: (x*2)

4.6Toposort: walking the DAG without recursion

Almost every analysis needs "every node, after all of its sources". toposort is an iterative DFS with an explicit stack of (node, visited) pairs. The first time a node is popped, it is pushed back with visited=True and its sources are pushed on top of it (reversed, so src[0] is handled first). The second time, all its sources are already done, so it is appended to the output.

tinygrad/uop/ops.py:281–293
  def toposort(self, gate:Callable|None=None, enter_calls=False) -> dict[UOp, None]:
    cache: dict[UOp, None] = {}
    stack: list[tuple[UOp, bool]] = [(self, False)] # each stack entry is (node, visited_flag)
    while stack:
      node, visited = stack.pop()
      if node in cache: continue
      if not visited:
        if gate is None or gate(node):
          stack.append((node, True))  # push node back on stack to process after its srcs
          for s in reversed(node.src if enter_calls else node.src_without_body):
            stack.append((s, False)) # push srcs on the stack
      else: cache[node] = None # second time i'm seeing this node, add it to returned toposort
    return cache
  • The result is a dict[UOp, None], an insertion-ordered set: you get O(1) membership and order together. backward_slice is this dict minus the node itself.
  • gate prunes the walk: a node for which gate(node) is false is neither emitted nor entered. recursive_property uses that to stop at nodes that already have the value cached.
  • src_without_body: a CALL's first source is the kernel body. It is not entered unless enter_calls=True, so a schedule walk doesn't descend into every kernel's AST.

4.7Building and changing graphs: const, variable, sink, replace, substitute

Since nodes can't be mutated, "changing" a graph always means building a new one that shares every untouched node with the old one:

  • replace(**kw) rebuilds one node with some fields swapped. It returns self if nothing changed, and because of hash-consing it returns an existing node if one matches.
  • substitute(dvars) replaces whole subgraphs everywhere they occur. It is one graph_rewrite with the matcher _substitute = PatternMatcher([(UPat(tuple(Ops), name="x"), lambda ctx,x: ctx.get(x,None))]), i.e. "if this node is a key of the dict, return its value", run bottom_up. So the engine of Chapter 5 is also the general graph-editing tool.
  • UOp.sink(*srcs) builds a SINK root, a void node whose sources are the outputs. Every kernel AST and every multi-output graph has one.
  • UOp.const(b, dtype) builds a CONST, plus a CAST when the dtype isn't the one CONST would derive. UOp.variable(name, lo, hi) builds a scalar PARAM in the ALU address space with vmin_vmax in its ParamArg. That is all a symbolic Variable is now (Chapter 6).
  • Operators come from mixins (tinygrad/mixin/elementwise.py): x*2 calls _binop(Ops.MUL, 2), which promotes dtypes and calls alu. x - y is built as x + y*-1, so you'll see that form in renders.

4.8Shape inference (_shape) and args that are graphs

In the tensor graph every node has a shape, and it is derived, like dtype. _shape is a big match that must handle every op explicitly (it ends with raise NotImplementedError). Late ops such as SINK, IF and LINEAR have shape None. CONST, RANGE and SPECIAL are scalars (). BUFFER and PARAM get their shape from their size source. Elementwise ops broadcast their sources' shapes. Movement ops compute a new shape from their "marg" (movement arg):

tinygrad/uop/ops.py:382–398

          return self.marg
        case Ops.EXPAND:
          return tuple(self.marg) + ps
        case Ops.PERMUTE:
          if sorted(self.marg) != list(range(len(ps))): raise ValueError(f"invalid permutation {self.marg} of len {len(ps)}")
          return tuple(ps[i] for i in self.marg)
        case Ops.PAD:
          # TODO: why do i need resolve here?

Notice self.marg, not self.arg. In this version a movement op's parameters are sources, not the arg: a RESHAPE is RESHAPE(x, STACK(CONST 3, CONST 4)), and marg reads them back as Python ints (ops.py:768). This is how shapes become symbolic: a dimension can be any int-valued UOp, such as a Variable n, and graph rewriting simplifies it like any other expression (Chapter 6). SHRINK and PAD carry two STACKs, with marg pairs (offset, size) and (offset, new_size) per axis. The user-facing (start, end) form is converted in MovementMixin.

4.9Three printers for one graph

  • repr(u) → pretty_print: valid-looking Python that reconstructs the graph. It first runs a DFS counting how many parents each node has; a node used more than once is printed once as x3:=UOp(...) and afterwards just as x3. That is the DAG's sharing made visible.
  • u.render_uir() → render_uir: an SSA "wire format", one line per non-constant node in toposort order: %i = op srcs : arg. Constants and all-constant STACKs are inlined as literals. This is the most readable format for big graphs, and what DEBUG=5 and the VIZ CLI print.
  • u.render() → an infix expression produced by the renderer PatternMatcher, used for index math. By default it simplifies first; render(simplify=False) shows the raw graph, which this guide uses to show "before" states.

def pretty_print(x:UOp, cache=None, d=0)->str:
  def dfs(x:UOp, cache:dict):
    for s in x.src:
      cache.setdefault(s, [len(cache), 0, False])[1] += 1
      if cache[s][1] == 1: dfs(s, cache)
  if cache is None: dfs(x, cache:={})
  if (cx:=cache.setdefault(x, [0,0,False]))[2]: return f"{' '*d}x{cx[0]}"
  cx[2], srcs = True, (''.join(f'\n{pretty_print(s, cache, d+2)},' for s in x.src))
  return f"{' '*d}{f'x{cx[0]}:=' * (cx[1]>1)}{type(x).__name__}({x.op}, arg={x.argstr()}, src=({srcs}))"

The SINK is the same kind of object as the kernel The schedule is a UOp too: LINEAR of CALLs, where each CALL's src[0] is the kernel AST and the rest are the BUFFERs it runs on. 4.12A preview: every int UOp knows its range

One more derived property matters everywhere: vmin/vmax, a conservative interval for the node's value, computed by _min_max from the sources' intervals. A Variable's interval is in its ParamArg, a RANGE's is [0, end-1], and ADD, MUL, DIV and MOD combine them. That lets symbolic simplification prove facts like "this mod is a no-op". 4.13Check yourself

Why can't you just do u.src = (a, b) to edit a graph?
Assigning a new tuple to the attribute is technically possible (the comment says "this should be frozen, but frozen is slower"), but it breaks every invariant: the ucache entry is keyed on the old (op, src, arg), every parent sharing u silently changes, and __dict__-cached properties are stale. Use replace/substitute/graph_rewrite.
In (x+y)*(x+y), how many ADD nodes exist, and how does repr show it?
The second x+y returns the cached object at construction, so no pass is needed. In the toposort demo the MUL has two edges to the same ADD.
Which of these is stored as a field on a UOp (not derived)?
UOp.__dataclass_fields__ is exactly op, src, arg. dtype comes from dtype_from_uop, shape from _shape, key from sha256; all are cached in __dict__ the first time they're read.
A kernel AST built in one process and an identical one built a week later in another process: what guarantees they share the compiled-program cache entry?
Identity is per-process; key is content-addressed. The name is part of the arg, so it is part of the key, but on its own it is not enough.

Chapter summary

  • A UOp stores only op, src, arg. dtype, shape, key, device, ranges and vmin/vmax are derived, cached, and computed iteratively (recursive_property).
  • Hash-consing (UOpMetaClass.ucache, keyed on (op, src, arg, type(arg)), holding weakrefs) makes structural equality the same as identity, gives free CSE and cheap dict keys, and forces immutability. __del__ evicts dead entries.
  • key is a content hash for caches that cross processes, such as the compiled-program cache.
  • Ops is ordered by role. The order matters through tuplize (linearizer tie-breaks, commutative canonicalization: consts go right). GroupOp names the families and algebraic properties that patterns match on.
  • toposort is an iterative DFS returning an ordered dict. replace/substitute build new graphs that share untouched nodes.
  • Movement args are sources (STACKs of CONSTs), which is what makes symbolic shapes possible.
  • The same class spans the tensor graph (shapes, movement), the kernel AST (RANGE/INDEX/STORE/SINK), and the linear program (LOAD/STORE/casts in a LINEAR). The schedule (LINEAR of CALLs) and PROGRAM are UOps too. Next: the engine that transforms one into the other, Chapter 5.
