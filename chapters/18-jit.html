CHAPTER 18TinyJit & functions

Every realize() re-runs the whole Python machine: build a lazy graph, rewrite it into a schedule, look things up in caches, dispatch each kernel. For a small model that Python work is most of the step time. TinyJit records the schedule once and replays it — a single run_linear of precompiled, memory-planned calls with only the input buffers swapped. This chapter takes apart engine/jit.py and the graph-level cousin function.py, and measures what the JIT buys on a CPU.

Version noteIn this version the JIT stores a LINEAR UOp (CapturedJit._linear), not a list of ExecItems/runners, and there are no GraphRunner classes (CUDAGraph, MetalGraph, HCQGraph…). Batching kernels into one submission is now done for every schedule on HCQ devices by hcq_compile (Chapter 17 §17.10); the JIT just calls the same compile_linear once, ahead of time.

18.1Intuition: a macro recorder

AnalogyA spreadsheet macro recorder. The first time you do the task by hand (so you know it works). The second time you press record: the recorder writes down every click, but it remembers which cell you clicked, not why. From then on you press play and it repeats the clicks in a blink — on whatever data is in the input cells now. Anything you decided in your head while recording (an if, a number you typed) is frozen into the macro.

TinyJit is exactly that, with three phases keyed by a call counter cnt:

callcntphasewhat happens
10ignore (warm-up)run your function normally; realize the returned tensors. Compiles every kernel, fills caches, lazily-initialized state (e.g. weights) gets realized.
21capturerun your function with the JIT registered in capturing: every schedule is recorded instead of executed. Then combine, parametrize inputs, memory-plan, compile, and run the result once.
3+≥2replaydon't call your function at all. Check the inputs match, then run_linear(captured, input_uops=…, jit=True).
The key ideaOn replay, your Python function is not executed. No Tensor ops, no graph, no scheduler, no cache lookups — just one loop over precompiled CALLs. Everything the function computed in Python during capture (shapes, branches, scalar arguments, .item() values) is baked in.

18.2_TinyJit.__call__, line by line

tinygrad/engine/jit.py — class _TinyJit
class _TinyJit(Generic[ReturnType]):
  def __init__(self, fxn:Callable[..., ReturnType]|None, captured:CapturedJit|None=None, prune=False):
    assert fxn or captured, "need either a function or a CapturedJit"
    self.fxn = fxn
    self.captured: CapturedJit|None = captured
    self.cnt: int = 2 if self.fxn is None else 0
    self.prune = prune

  def add_linear(self, linear:UOp): self._linears.append(linear)

  def reset(self):
    assert self.fxn is not None, "can't reset without function"
    self.cnt = 0
    self.captured = None

  def __reduce__(self):
    assert self.captured is not None, "can't pickle an uncaptured JIT"
    return self.__class__, (None, self.captured)

  def __get__(self, obj, objtype): return functools.partial(self.__call__, obj) # add support for instance methods

  @disable_gc()
  def __call__(self, *args, **kwargs) -> ReturnType:
    input_buf_uops, var_vals, names, expected_input_info = _prepare_jit_inputs(args, kwargs)
    if not JIT or self.cnt == 0:
      # jit ignore
      assert self.fxn is not None
      with Context(BEAM=0 if getenv("IGNORE_JIT_FIRST_BEAM") else BEAM.value):
        ret = self.fxn(*args, **kwargs)
        if len(params:=get_parameters(ret)): Tensor.realize(*params)
    elif self.cnt == 1:
      # jit capture
      assert self.fxn is not None
      if capturing: raise RuntimeError(f"having TinyJit inside another TinyJit is not supported {len(capturing)=} {capturing=}")
      self._linears: list[UOp] = []
      capturing.append(self)
      try:
        ret = self.fxn(*args, **kwargs)
        if len(params:=get_parameters(ret)): Tensor.realize(*params)
      finally: capturing.clear()
      if not len(self._linears): raise JitError("didn't JIT anything!")
      _check_no_non_tensor_return(ret)
      if DEBUG >= 1: print(f"JIT captured {len(self._linears)} linears with {len(input_buf_uops)} inputs")

      # combine all captured linears into one, memory plan, and compile
      big_linear = UOp(Ops.LINEAR, src=tuple(flatten([l.src for l in self._linears])))
      del self._linears

      if self.prune:
        big_linear, onetime_linear = prune_linear(big_linear, set(input_buf_uops))
        if DEBUG >= 1: print(f"pruned from {len(big_linear.src) + len(onetime_linear.src)} -> {len(big_linear.src)} kernels")
        run_linear(onetime_linear, var_vals)
        del onetime_linear

      # hold all buffers with real storage reachable from live Tensors (e.g. lazy .grad created during capture) and all buffers with
      # allocated storage in the captured linear (e.g. constants baked in by copies): the memory planner can't suballocate those
      def _buf_or_none(u:UOp) -> Buffer|MultiBuffer|None: return u.arg.buffer if u.op is Ops.BUFFER else None
      held_bufs = {u for tref in list(all_tensors) if (t:=tref()) is not None for u in t.uop.toposort() if _buf_or_none(u) is not None}
      held_bufs |= {u for u in big_linear.toposort() if (b:=_buf_or_none(u)) is not None and b.is_allocated()}
      linear = jit_lower(big_linear, held_bufs, input_buf_uops, var_vals)
      # drop the pre-planning graph: it keeps the whole capture-time working set allocated (big_linear) or referenced (held_bufs).
      # the planned linear only uses the arena/held buffers, so the intermediates must be freed before linking and first exec
      del big_linear, held_bufs
      self.captured = CapturedJit(ret, linear, names, expected_input_info)
      ret = self.captured(input_buf_uops, var_vals)
    elif self.cnt >= 2:
      # jit exec
      assert self.captured is not None
      if self.captured.expected_names != names: raise JitError(f"args mismatch in JIT: {self.captured.expected_names=} != {names}")
      if self.captured.expected_input_info != expected_input_info:
        raise JitError(f"args mismatch in JIT: {self.captured.expected_input_info=} != {expected_input_info=}")
      ret = self.captured(input_buf_uops, var_vals)

    self.cnt += 1
    return ret

Notes on the details:

  • JIT=0 makes every call take the "ignore" branch — a quick way to check whether a bug is the JIT's fault.
  • @disable_gc(): Python's GC is paused during the call; a GC pause in the middle of a step is jitter you don't want.
  • Nested JITs are refused (capturing is a single global list).
  • __get__ makes @TinyJit work on methods (self becomes the first argument — it's not a Tensor so it's not an input).
  • prune=True splits off the calls that don't depend on any input (e.g. weight preprocessing) and runs them once, so they're not replayed.
  • The returned object is the same Python object (and the same Buffers) every replay — CapturedJit.ret.

18.3Capture: recording schedules instead of running them

How can the JIT see the kernels your function launches? The hook is at the very end of scheduling. When the global capturing list (in realize.py) is non-empty, create_linear_with_vars hands the finished LINEAR to the JIT and returns an empty LINEAR, so run_linear has nothing to do:

tinygrad/schedule/__init__.py — the capture hook
  # jit captures this schedule, no need to execute.
  if len(capturing) and CAPTURING:
    capturing[0].add_linear(linear)
    return UOp(Ops.LINEAR, src=()), var_vals

  held_bufs = {b for b in linear_call.src[1:] if b.op is Ops.BUFFER}

So during capture, every realize() inside your function (explicit, or implicit via the returned tensors) appends one LINEAR to self._linears, and nothing executes. Which immediately explains the most important restriction — reading data during capture is impossible, because the data doesn't exist yet:

tinygrad/tensor.py — Tensor._buffer (used by .item(), .tolist(), .numpy(), .data())
  def _buffer(self) -> Buffer:
    from tinygrad.engine.realize import capturing

      raise JitError("cannot access tensor data during JIT capture, the value will be baked in")
    x = self.contiguous()
    if self.uop.device is None or isinstance(self.device, tuple): x = x.clone("CPU")
    return cast(Buffer, x.realize().uop.buffer).ensure_allocated()

(Note the message: even if it could read, the value would be baked in — the replay never re-runs your Python.)

From recorded LINEARs to a replayable program: jit_lower

tinygrad/engine/jit.py — jit_lower
@rewrite_group(lambda linear,held_bufs,input_uops,input_vars,ret=(): f"JIT {pluralize('call', len(linear.src))}")
def jit_lower(linear:UOp, held_bufs:set[UOp], input_uops:list[UOp], input_vars:dict[str, int]) -> UOp:
  if VIZ: graph_rewrite(linear, PatternMatcher([]), name="View captured linear")

  # parametrize input buffers: map each input buffer UOp to a PARAM with the correct slot index
  linear = linear.substitute({u: UOp.param(i, u.dtype, u.max_numel(), u.device) for i,u in enumerate(input_uops)}, walk=True)
  # unbind input variables, they change every call and are read from var_vals. any other binding was fixed at capture and stays
  linear = linear.substitute({v: v.unbound() for v in linear.toposort() if v.is_bound_var and v.expr in input_vars}, walk=True)
  linear = memory_plan_rewrite(linear, held_bufs)
  scratch = {u: UOp.alloc((u.max_numel(),), u.dtype, device=u.device) for u in linear.toposort() if u.op is Ops.BUFFER and u not in held_bufs}
  linear = linear.substitute(scratch, walk=True)
  linear = compile_linear(linear, beam=getenv("JITBEAM", BEAM.value), input_uops=input_uops, cache=False)
  if VIZ: graph_rewrite(linear, PatternMatcher([]), name="View compiled linear")
  return linear

Inputs → transformation → output, step by step:

  1. Concatenate all captured LINEARs into big_linear (in __call__).
  2. Parametrize inputs: every input buffer UOp (one per Tensor argument, found by _prepare_jit_inputs) is substituted by UOp.param(i, …). Slot i = position in the input list. This is the "input buffer replacement": the program now reads input i through a parameter instead of a fixed buffer.
  3. Unbind input Variables: a Variable("n").bind(5) passed in becomes unbound, so its value is read from var_vals at every replay. Bindings that were not inputs stay fixed.
  4. Memory plan (memory_plan_rewrite, Chapter 12): all intermediates that are not held_bufs get lifetimes and are suballocated into shared arenas. Held = anything reachable from a live Tensor (weights, the returned outputs, a lazily created .grad) or already allocated (constants copied in).
  5. Scratch → ALLOC: remaining unplanned BUFFERs become ALLOC placeholders, bound to fresh storage at link time.
  6. Compile with compile_linear (BEAM taken from JITBEAM, falling back to BEAM). On HCQ devices this is also where the whole step is batched into one host submit program.

Then CapturedJit(ret, linear, names, expected_input_info) is built and immediately called with the capture's inputs — so call 2 does compute real outputs.

18.4Replay: CapturedJit.__call__

tinygrad/engine/jit.py — CapturedJit
@dataclass
class CapturedJit(Generic[ReturnType]):
  ret: Any  # includes the Tensors or any other returned object
  _linear: UOp
  expected_names: list[int|str]
  expected_input_info: list[tuple[UOp, tuple[Variable, ...], DType, str]]  # (view, variables, dtype, device) per input
  _linears: dict[tuple[UOp, ...], tuple[UOp, dict[UOp, UOp]]] = field(default_factory=dict)  # aliased inputs -> (linked linear with copies, staging)

  def __reduce__(self): return self.__class__, (self.ret, self._linear, self.expected_names, self.expected_input_info)

  @functools.cached_property
  def _jit_bufs(self) -> set[UOp]: return {u for u in self._linear.toposort() if u.op is Ops.BUFFER}

  @functools.cached_property
  def _symbolic_ret(self) -> list[tuple[Tensor, UOp, dict[Variable, int]]]:
    return [(t, *ub) for t in get_parameters(self.ret) if (ub:=t.uop.unbind_all())[1]]

  def __call__(self, input_uops:list[UOp], var_vals:dict[str, int]) -> ReturnType:
    # aliased inputs
    if (aliased:=tuple(u for u in input_uops if u in self._jit_bufs)) not in self._linears:
      if any(u.on_disk() for u in aliased): raise JitError("cannot make an independent copy of a written DISK input")
      staging = {u: UOp.new_buffer(u.device, u.max_numel(), u.dtype) for u in aliased}
      copies = compile_linear(UOp(Ops.LINEAR, src=tuple(s.store_call(u) for u,s in staging.items())))
      self._linears[aliased] = (link_linear(self._linear.replace(src=copies.src+self._linear.src)), staging)

    linear, staging = self._linears[aliased]
    if DEBUG >= 1 and len(linear.src) >= 10: print(f"jit execs {len(linear.src)} calls")
    run_linear(linear, var_vals, input_uops=[staging.get(u, u) for u in input_uops], jit=True)
    for t,u,vals in self._symbolic_ret: t.uop = u.substitute({v:v.bind(var_vals.get(v.expr, i)) for v,i in vals.items()}, walk=True)
    return self.ret

  def free_intermediates(self): self._linears.clear()
  • Linking is done once per alias pattern. _linears caches the linked program keyed by which inputs alias the JIT's own buffers. Normally that tuple is empty, so link_linear runs on the first replay only.
  • Aliased inputs. If you feed the JIT's own output back in as an input (common in RNNs/KV caches: x = step(x)), the input would be overwritten while being read. The JIT detects this and prepends staging copies (staging[u] = new buffer, copy u → staging) and passes the staging buffer instead.
  • The run. run_linear(linear, var_vals, input_uops, jit=True): with jit=True it skips compile and link and goes straight to pm_exec for each CALL. exec_kernel's _resolve maps PARAM(slot) → input_uops[slot].
  • Symbolic outputs. If a returned tensor has a symbolic shape, its UOp is re-bound to the new Variable values (_symbolic_ret) so out.shape reflects this call.

The guard: _prepare_jit_inputs

def _prepare_jit_inputs(args, kwargs):
  input_tensors: list[tuple[int|str, Tensor]] = [(name,t) for name,t in list(enumerate(args))+sorted(kwargs.items()) if t.__class__ is Tensor]
  names, tensors = [name for name,_ in input_tensors], [t for _,t in input_tensors]
  # extract tensors from containers (shallow, not recursive to avoid grabbing model weights)
  for x in args + tuple(kwargs.values()):
    it = x if isinstance(x, (tuple,list)) else x.values() if isinstance(x, dict) else []
    tensors += [t for t in it if t.__class__ is Tensor and not any(t is y for y in tensors)]
  def get_input_uops() -> list[UOp]: return flatten([[t.uop.src[0]] if t.uop.op is Ops.UNSHARD else [t.uop] for t in tensors])
  if any(u.is_virtual for u in get_input_uops()): raise JitError("JIT inputs must be real buffers; use .clone()")
  if len(unrealized_tensors := [x for x in tensors if not x.uop.is_realized]): Tensor.realize(*unrealized_tensors)
  input_uops = get_input_uops()
  # collect buffer UOps (including MultiBuffer)
  input_buf_uops: list[UOp] = [u.base for u in input_uops if u.base.realized is not None]
  if len(set(input_buf_uops)) != len(input_buf_uops): raise JitError("duplicate inputs to JIT")
  inputs = [(*(u.substitute({u.base:UOp(Ops.NOOP)}, extra_pm=mop_cleanup).unbind_all()), u.dtype, u.device) for u in input_uops]
  _var_vals = merge_dicts([x[1] for x in inputs] + [dict(v.unbind() for v in (args + tuple(kwargs.values())) if isinstance(v, UOp))])
  var_vals = {k.expr:v for k,v in _var_vals.items()}
  expected_input_info = [(x[0], tuple(sorted(x[1].keys(), key=lambda v: v.expr)), x[2], x[3]) for x in inputs]
  return input_buf_uops, var_vals, names, expected_input_info

Inputs are Tensors in positional args and kwargs (plus Tensors directly inside a list/tuple/dict arg — shallow, so a model object passed as an argument is not treated as inputs). They're realized first; then for each input the JIT records (view, variables, dtype, device) — the view is the movement-op chain with the base replaced by NOOP. Replay compares names and this info and raises JitError("args mismatch in JIT…") on any difference.

A sharp edge (verified)The size of a plain contiguous 1-D input is not in its view (the view is just NOOP), so calling a JIT captured on a 3-element vector with a 4-element vector raises nothing and silently runs the 3-element kernels (§18.6, "size change"). A 2-D input carries a RESHAPE in its view, so a shape change there is caught. Treat "same shapes every call" as your responsibility, and use Variables for dimensions that change.
During the capture call (call 2), how many kernels are executed and when?
While recording, create_linear_with_vars returns an empty LINEAR, so nothing runs. Then ret = self.captured(input_buf_uops, var_vals) executes the planned program once. The example shows 5 kernels on call 2.

18.5Symbolic variables in the JIT

To JIT a function whose sizes change (sequence length, KV-cache position), pass the changing integer as a bound Variable. It becomes a kernel argument instead of a constant: jit_lower unbinds it, the kernel reads it from var_vals, and loop bounds/launch dims are symbolic (ProgramInfo.launch_dims(var_vals), Chapter 6).

v = Variable("n", 1, 8)              # name, min, max — max sizes the buffers
@TinyJit
def f5(x, n): return x[:n].sum().realize()
[f5(big, v.bind(n)).item() for n in (2, 3, 5, 8)]   # -> [3.0, 6.0, 15.0, 36.0]  (one capture, four sizes)

Compare the plain Python int version: f2(x, k) captured with k=2 returns x*2 forever (next section).

Read each line against the mechanism:

  • item inside → _buffer() raises during capture.
  • python scalar baked → call 1 used k=1, capture used k=2; the constant 2 is in the kernel. Calls 3 and 4 return ×2.
  • shape change (2-D) → caught by expected_input_info. size change (1-D) → not caught (see the warning above).
  • duplicate → the same buffer twice would get two PARAM slots aliasing each other; refused.
  • variable → correct for every n.
  • nothing → the function never realized anything new (it returned its input): didn't JIT anything!
  • rand → different numbers every replay. Random state is a buffer (a counter updated by a kernel), not a Python value, so it advances inside the replayed program.

# Chapter 18 — measure the Python overhead the JIT removes, for a small MLP on the CPU.
# run: DEV=CPU python3 examples/18_jit_timing.py      (writes data/ch18_timings.json)
import time, json, pathlib
from tinygrad import Tensor, TinyJit, nn
from tinygrad.engine.realize import run_linear
from tinygrad.helpers import GlobalCounters

N = 40
def med(xs): return sorted(xs)[len(xs)//2]

def run_config(inp, hidden, out, batch):
  Tensor.manual_seed(0)
  l1, l2 = nn.Linear(inp, hidden), nn.Linear(hidden, out)
  def forward(x): return l2(l1(x).relu()).log_softmax()
  def step(x): return forward(x).realize()
  jstep = TinyJit(step)
  xs = [Tensor.randn(batch, inp).realize() for _ in range(N)]

  def bench(f):
    ts = []
    for x in xs:
      st = time.perf_counter(); f(x); ts.append((time.perf_counter() - st) * 1e3)
    return ts
  plain, jit = bench(step), bench(jstep)

  # where does the non-JIT time go? build the lazy graph / schedule it / run it (compile+link+exec)
  phases = {"build graph": [], "schedule (linear_with_vars)": [], "run_linear (compile+link+exec)": []}
  for x in xs:
    t0 = time.perf_counter(); y = forward(x)
    t1 = time.perf_counter(); lin, vv = Tensor.linear_with_vars(y)
    t2 = time.perf_counter(); run_linear(lin, vv)
    t3 = time.perf_counter()
    for k, d in zip(phases, (t1 - t0, t2 - t1, t3 - t2)): phases[k].append(d * 1e3)
  ncalls = len(lin.src)

  # how many kernels does one JIT replay launch?
  GlobalCounters.reset(); jstep(xs[0]); kcount = GlobalCounters.kernel_count
  return {"shape": f"{inp}->{hidden}->{out}, batch {batch}", "plain_ms": plain, "jit_ms": jit,
          "phases_ms": {k: med(v[5:]) for k, v in phases.items()}, "calls": ncalls, "kernels_per_replay": kcount,
          "plain_median": med(plain[5:]), "jit_median": med(jit[5:])}

results = [run_config(64, 128, 10, 16), run_config(784, 1024, 10, 64)]
for r in results:
  print(f"MLP {r['shape']}: {r['calls']} CALLs per step")
  print(f"  without JIT : first calls {[round(t, 2) for t in r['plain_ms'][:3]]} ms, median {r['plain_median']:.3f} ms")
  print(f"  with TinyJit: first calls {[round(t, 2) for t in r['jit_ms'][:3]]} ms, median {r['jit_median']:.3f} ms"
        f"  -> {r['plain_median']/r['jit_median']:.1f}x faster")
  print("  non-JIT breakdown (median):", {k: round(v, 3) for k, v in r["phases_ms"].items()})
path = pathlib.Path(__file__).resolve().parent.parent / "data" / "ch18_timings.json"
path.write_text(json.dumps(results))

What the numbers say:

  • Only the very first call is ~0.5 s — that's compilation (clang, plus the first schedule), paid by the non-JIT run that went first. Non-JIT call 2 is still ~30 ms (likely because call 1 also realized the lazy weight initialization, so the graph differs), then ~9 ms steady. The JIT run came second with warm caches: its calls 1 and 2 (warm-up and capture) cost about a normal non-JIT step, and from call 3 on it replays.
  • The small MLP is pure overhead. Without the JIT ≈9.4 ms per step: ~1.5 ms building the lazy graph, ~4.4 ms scheduling (even with the schedule cache hit, the graph must be hashed and rewritten), ~3.5 ms in run_linear (cache lookups, linking, dispatch of 5 kernels, plus the kernels themselves). With the JIT ≈0.6 ms: ~15× faster.
  • Bigger model, smaller win. At 784→1024→10, batch 64, the kernels themselves take ~6 ms, so the JIT's ~9 ms saving gives 2.4×. The JIT removes overhead; it does not make kernels faster.
  • On GPUs the effect is larger still: replay goes through one batched HCQ submission, so the per-kernel cost is a few command words.
A model's kernels take 20 ms per step on the GPU, and Python overhead without the JIT is 8 ms. Roughly what does TinyJit give?
The JIT removes Python work, not kernel time. On a GPU, async launches can already overlap some Python with execution, so the real gain may be smaller still.

18.8@function: capture at the graph level

TinyJit captures after scheduling: a list of compiled kernels. @function captures before scheduling: it turns a Python function into a single CALL UOp in the lazy tensor graph, whose body is the function's graph with every input replaced by a PARAM. Nothing runs when you call it, and it composes with autograd, other functions, the JIT, and multi-device.

tinygrad/function.py — _function.__call__
  def __call__(self, *args, **kwargs) -> ReturnType:
    st = time.perf_counter()

    params = get_state_dict((args, kwargs), tensor_type=(Tensor, UOp)).values()

    # deduplicate input_uops, keeping the first occurrence index for each unique uop
    call_uops: list[UOp] = dedup([u for t in params if (u:=t._uop).device is not None])

    # disable realize/schedule while this is running
    # run it and do surgery later
    alloc_start = next(UOp.unique_num)
    with Context(ALLOW_DEVICE_USAGE=getenv("DEVICE_IN_FUNCTION_BUG", 0)):
      _function.depth += 1
      try:
        ret = self.fxn(*args, **kwargs)
      finally:
        _function.depth -= 1
    if isinstance(ret, Tensor):
      uret = ret.uop
    elif isinstance(ret, tuple) and all(isinstance(x, Tensor) for x in ret):
      uret = UOp.sink(*[x.uop for x in ret])
    else:
      raise RuntimeError(f"function return type {type(ret)} not supported")

    # replace the known inputs with params (using deduplicated slots)
    subs = {x:x.param_like(i) for i,x in enumerate(call_uops)}
    uret = uret.substitute(subs)

    # caller-owned storage left in the graph becomes implicit inputs
    num_explicit = len(call_uops)
    uret = graph_rewrite(uret, pm_ctx, (call_uops, invalid_outputs(uret), alloc_start), bottom_up=True, name="get_implicit_inputs")
    uret = renumber_invalid_outputs(uret)
    name = getattr(self.fxn, '__qualname__', None) or type(self.fxn).__qualname__
    if not self.allow_implicit:
      implicit_buffers = [x for x in call_uops[num_explicit:] if x.op in {Ops.BUFFER, Ops.ALLOC}]
      if implicit_buffers:
        buf_strs = '\n  '.join(f"{i}: dtype={b.dtype}, size={b.max_numel()}, device={b.device}" for i,b in enumerate(implicit_buffers))
        raise RuntimeError(f"function {name} has {len(implicit_buffers)} implicit buffer(s), but allow_implicit=False\n  {buf_strs}")

    outs = UOp.call_with_outputs(uret.src if isinstance(ret, tuple) else (uret,), *call_uops, grad_fxn=self.grad_fxn, name=name,
                                 precompile=self.precompile, precompile_backward=self.precompile_backward)

    if DEBUG >= 2:
      print("  "*_function.depth+f"function {uret.key.hex()[:8]} in {(time.perf_counter()-st)*1000:8.2f} ms: {name}")

    if isinstance(ret, tuple):
      return cast(ReturnType, tuple(Tensor(o) for o in outs))
    else:
      return cast(ReturnType, Tensor(outs[0]))
  1. Collect the Tensor/UOp arguments (via get_state_dict, so nested structures work) → call_uops.
  2. Run the Python function with ALLOW_DEVICE_USAGE=0: building the graph is fine, realizing is not.
  3. Replace each input by x.param_like(i).
  4. Implicit inputs (pm_ctx): any caller-owned storage still in the graph — a global weight you closed over — becomes an extra parameter. With the default allow_implicit=False this raises, listing the buffers.
  5. Build the CALL with UOp.call_with_outputs: outputs become ALLOCs passed as extra args, and the returned Tensors are output.after(call).

Why bother, if the function is inlined anyway (is_inline_call: True — pm_inline_calls in schedule/prepare.py substitutes the body back in)? Because of hash-consing: calling layer on a new input yields the same body UOp ("same body object: True"), so a model that applies one layer 32 times has one body, not 32 copies — graph building, hashing and the schedule cache all get cheaper. With precompile=True the body is scheduled once on its own (lower_sink_to_linear, keyed by the body) into a reusable LINEAR, and calls only bind parameters — that's how the LLM in tinygrad/llm/model.py uses it. grad_fxn lets you supply a custom backward.

18.9Hammer it again: a training step under the JIT

The canonical use, from examples/beautiful_mnist.py (see Chapter 20):

  @TinyJit
  @Context(TRAINING=1)
  def train_step(self, X_train:Tensor, Y_train:Tensor) -> Tensor:
    opt.zero_grad()
    samples = Tensor.randint(getenv("BS", 512), high=X_train.shape[0])
    loss = self(X_train[samples]).sparse_categorical_crossentropy(Y_train[samples]).backward()
    return loss.realize(*opt.schedule_step())
  • Weights and optimizer state are held buffers (reachable from live Tensors), updated in place by the captured kernels via STORE/AFTER — so the replay really trains.
  • The learning rate as a Python float would be baked in; tinygrad's optimizers keep lr as a Tensor so schedulers can change it.
  • Returning loss without realizing weight updates would capture only the loss kernels — the updates would never run. That's why the step realizes them together.
  • Printing loss.item() outside the jitted function is fine (it's a normal read of the returned buffer).
  • Note the batch is sampled inside the step with Tensor.randint: the random indices come from the RNG buffer, so each replay trains on a new batch while X_train (a JIT input) stays the same buffer.
  • Data loading must produce real buffers: JitError("JIT inputs must be real buffers; use .clone()") for virtual inputs (e.g. a broadcast const).
You JIT def step(x): return model(x) if x.shape[0] > 1 else model(x[0:1]) and always call it with batch 32. Problem?
Branching on shapes is fine as long as the shapes don't change between calls — and with 2-D inputs a change is caught by the input check. Branching on data (.item()) is what's forbidden.

Chapter summary

  • TinyJit phases: cnt=0 run normally (warm-up), cnt=1 capture, cnt≥2 replay without running your Python.
  • Capture works by a hook in create_linear_with_vars: with capturing set, LINEARs are recorded and an empty LINEAR is returned. Reading data raises JitError.
  • jit_lower: inputs → PARAM(i), input Variables unbound, intermediates memory-planned, scratch → ALLOC, then compile_linear once.
  • Replay = run_linear(linked, var_vals, input_uops, jit=True); linking is cached; aliased inputs get staging copies; symbolic output shapes are re-bound.
  • Baked in: Python scalars, branches, shapes, the returned objects. Live: input buffers, bound Variables, buffers updated in place (weights, RNG counter).
  • On a CPU the small MLP went from ~9.4 ms to ~0.6 ms per step (15×); a heavier one 2.4× — the JIT removes overhead, not kernel time.
  • @function captures a graph-level CALL (PARAMs for inputs, implicit inputs opt-in, hash-consed body, optional precompile).
