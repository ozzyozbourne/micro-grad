CHAPTER 19Multi-device & sharding

A sharded tensor is one logical tensor whose storage is split (or replicated) across several devices. tinygrad does not have a separate "distributed" engine: sharding is more UOps — an UNSHARD wrapper with a DEVICE range, a rewrite (multi_pm) that pushes every op down to the per-device shards, COPY/MSELECT/MSTACK to move data between devices, and an ALLREDUCE that is expanded into plain copies and adds. We run everything on several CPU "devices" (CPU, CPU:1, CPU:2…) and look at the real kernels and copies.

Version noteOlder tinygrad had a MultiLazyBuffer and later an Ops.MULTI UOp holding (axis, real). In this version a sharded value is UNSHARD(value, RANGE(DEVICE)) with arg=(axis,), storage is a MultiBuffer, a multi-device kernel is launched once per device with a _device_num argument, and the schedule-level rewrite lives in schedule/multi.py and schedule/allreduce.py.

19.1Intuition: one tensor, many hands

AnalogyGrading a stack of 1000 exams with 4 teachers. Split the stack by rows (shard on axis 0): each grades 250, no talking needed. Ask "what's the average score of question 3?" and each teacher sums their own 250, then they must combine their partial sums — that's an allreduce. Give every teacher a full copy of the answer key (replicated, axis=None) so nobody has to ask for it. The art of sharding is choosing splits so that most work needs no talking.

Three ideas carry the whole chapter:

  1. The device range. A sharded value is described by a symbolic RANGE of AxisType.DEVICE — "I am device r of n". Shard r of a tensor sharded on axis 0 is x[r*sz : r*sz+sz]. One UOp graph describes all shards.
  2. Push-down. multi_pm rewrites op(UNSHARD(a), UNSHARD(b)) into UNSHARD(op(a, b)) whenever that's legal: elementwise ops, reshapes and reductions over non-sharded axes run independently per device.
  3. Communication is explicit. When the push-down isn't legal (a reduction over the sharded axis, a gather to one device, a reshard), the rewrite inserts COPYs and an ALLREDUCE, which later become copy CALLs and add kernels.

19.2Creating a sharded tensor

tinygrad/tensor.py — Tensor.shard / shard_ / shard_like
  def shard(self, devices:tuple[str, ...], axis:int|None=None) -> Tensor:
    """
    Shards the tensor across the given devices. Optionally specify which axis to shard on.

    ```python exec="true" source="above" session="tensor" result="python"
    t = Tensor.empty(2, 4)
    print(t.shard((t.device, t.device), axis=1).uop)
    ```
    """
    if self.uop.device is None: return self
    if not isinstance(self.device, str): raise RuntimeError("can't shard a multi-device tensor")
    if len(devices) == 1: return self.to(devices[0])
    devices = cast(tuple[str, ...], canonicalize_device(devices))
    # a shard of a load from a creation device (disk/npy/python) wants the copy to persist, so it inserts a clone
    src = self.uop.clone(devices) if self.uop.on_creation_device() else self.uop
    uop = src.shard(devices, None if axis is None else self._resolve_dim(axis))
    return Tensor(uop).is_param_(self.is_param)

  def shard_(self, devices:tuple[str, ...], axis:int|None=None) -> Tensor:
    """
    Shards the tensor across the given devices in place.
    """
    return self.replace(self.shard(devices, axis))

  def shard_like(self, y:Tensor) -> Tensor:
    """
    Shards the tensor the same way as `y` (same devices and axis).
    """
    if y.device is None: return self
    if isinstance(y.device, str): return self.to(y.device)
    return self if isinstance(self.device, tuple) and (y.device, y.uop.axis) == (self.device, self.uop.axis) else self.shard(y.device, y.uop.axis)
tinygrad/uop/ops.py — UOp._shard / shard / copy_to_device / mselect / mstack
  def _shard(self, axis:int, rng:UOp) -> UOp:
    if len(self.shape) == 0: return self  # scalars broadcast, no sharding needed
    dcount = int(rng.vmax)+1
    if self.shape[axis] % dcount != 0: raise RuntimeError(f"multi axis uneven: {self.shape[axis]=} {axis=} {dcount=}")
    sz = self.shape[axis] // dcount
    return self.shrink(tuple((0,s) if i != axis else (rng*sz,rng*sz+sz) for i,s in enumerate(self.shape)))
  def shard(self, devices:tuple[str, ...], axis:int|None=None) -> UOp:
    copied = self.copy_to_device(devices)
    return copied if axis is None else copied._shard(axis, UOp.range(len(devices), 0, AxisType.DEVICE)).unshard(axis)

  def copy_to_device(self, device:str|tuple[str, ...]):
    if is_disk_device(device):
      raise RuntimeError("COPY to DISK is not allowed; use STORE to an explicit disk buffer")
    if self.dtype in dtypes.weaks: raise RuntimeError(f"cannot create storage for weak dtype {self.dtype}")
    # multi-device COPYs carry the DEVICE range as src[1] (like UNSHARD's sharding ranges)
    return UOp(Ops.COPY, src=(self, *UOp.device_range_src(device)), arg=device)
  def store_call(self, src:UOp) -> UOp:
    """Executable bulk transfer into this buffer."""
    return self.param_like(0).store(src.param_like(1)).call(self, src)
  def mselect(self, arg:int) -> UOp: return UOp(Ops.MSELECT, src=(self,), arg=arg)
  def mstack(self, *srcs: UOp) -> UOp: return UOp(Ops.MSTACK, src=(self,)+srcs) if len(srcs) else self

So t.shard(devs, axis=0) builds:

UNSHARD(arg=(0,))                                   # "this value is sharded on axis 0 over range r"
 ├─ SHRINK( (r*2, r*2+2), (0, 4) )                  # shard r = rows [2r, 2r+2)
 │   └─ COPY(arg=('CPU','CPU:1'), src=(t, r))        # t broadcast to every device
 └─ r = RANGE(DEVICE, 2)

Read it as math, not as an algorithm: "copy to all devices, then on device r keep rows [2r, 2r+2)". The scheduler later fuses the shrink into the copy, so each device only receives its own slice (you'll see one 32-byte copy, not two full copies). The helper unshard() and the properties around it:

  def unshard(self, axis:int|tuple[int, ...]|None, device_range:UOp|tuple[UOp, ...]|None=None):
    assert axis is not None, "multi None is no longer supported"
    # an UNSHARD carries the value and one sharding range per sharded axis (arg is the tuple of sharded axes,
    # sorted). the single-axis axis form defaults the range to a DEVICE range over the devices; a range need not
    # be DEVICE, e.g. a LOCAL range shards a kernel tile into per-thread fragments
    if isinstance(axis, int): axis = (axis,)
    if device_range is None:
      assert isinstance(self.device, tuple), f"multi device must be tuple, {self.device} isn't"
      device_range = (UOp.range(len(self.device), 0, AxisType.DEVICE),)
    if isinstance(device_range, UOp): device_range = (device_range,)
    assert isinstance(device_range, tuple) and len(axis) == len(device_range) and len(set(axis)) == len(axis)
    axis, device_range = map(tuple, zip(*sorted(zip(axis, device_range))))
    return UOp(Ops.UNSHARD, src=(self, *device_range), arg=axis)

  @property
  def sharding(self) -> tuple[tuple[int, UOp], ...]:
    """(axis, RANGE) pairs this value is sharded over (the source of truth for shard bounds/counts)."""
    return tuple(zip(self.arg, self.src[1:])) if self.op is Ops.UNSHARD else ()

  @functools.cached_property
  def axis(self) -> int|None:
    # COPY removes axis. TODO: add more tests for this, and consider MSELECT/MSTACK
    if self.op is Ops.COPY: return None
    if self.op is Ops.UNSHARD:
      if len(self.arg) != 1: raise RuntimeError(f"UOp is sharded on multiple axes {self.arg}, use .sharding")
      return self.arg[0]
    # NOTE: they all have to share an axis, we always choose [-1]. src axes are right-aligned into the output shape
    if self.op in GroupOp.ALU.union({Ops.STACK}):
      return axes[-1] if (axes := dedup([x.axis+len(self.shape)-len(x.shape) for x in self.src if x.axis is not None])) else None
    if len(self.src) == 0: return None
    src_axis = self.src[0].axis
    if self.op is Ops.SHRINK and src_axis is not None and self.marg[src_axis] != (0, self.src[0].shape[src_axis]):
      return None # SHRINK will remove the sharding if it's on axis
    if self.op is Ops.REDUCE:
      if src_axis is None: return None
      if src_axis < self.arg[1]: return None
      return src_axis - self.arg[1]
    if self.op is Ops.RESHAPE:
      if src_axis is None: return None
      arg_acc:list[sint] = [ssimplify(x) for x in itertools.accumulate(self.marg, operator.mul, initial=1)]
      # new_axis is the last one that preserves prod(prior to new_axis) and must not move items between shards
      target = ssimplify(prod(self.src[0].shape[:src_axis]))
      if target not in arg_acc: raise RuntimeError(f"reshape {self.src[0].shape} -> {self.shape} moved items between shards")
      new_axis = len(arg_acc) - arg_acc[::-1].index(target) - 1
      dcount = len(self.device) if isinstance(self.device, tuple) else \
        int(next(u.src[1] for u in self.src[0].toposort() if u.op is Ops.UNSHARD).vmax)+1
      if self.shape[new_axis] % dcount != 0: raise RuntimeError(f"reshape {self.src[0].shape} -> {self.shape} moved items between shards")
      return new_axis
    if self.op is Ops.PERMUTE: return self.marg.index(src_axis) if src_axis is not None else None
    if self.op is Ops.EXPAND: return src_axis + len(self.marg) if src_axis is not None else None
    return src_axis
  • axis is a derived property computed through the graph: a PERMUTE moves it, an EXPAND shifts it, a REDUCE over it erases it, a RESHAPE must keep the shard boundary intact or raise "reshape … moved items between shards", a COPY to one device removes it.
  • Uneven splits are rejected (_shard requires shape[axis] % n == 0).
  • Device names are canonicalized: ("CPU:0","CPU:1") becomes ('CPU', 'CPU:1'); Device["CPU:1"] is a second CPUDevice instance (Chapter 17).

19.3multi_pm: pushing ops through UNSHARD

Sharded tensors flow through the normal Tensor API, building a normal lazy graph with UNSHARD nodes inside. At schedule time, prepare_rangeify runs graph_rewrite(sink, multi_pm) first thing (schedule/prepare.py:257), and the result has UNSHARDs only at the top. Here is the matcher:

The two rules that matter most:

tinygrad/schedule/multi.py — alu_multi / reduce_multi
def alu_multi(root:UOp):
  multis = [m for m in root.src if m.op is Ops.UNSHARD]
  sharding = multis[0].sharding
  target = multis[0]
  def can_handle(m:UOp) -> bool:
    # same sharding (peel the UNSHARD), or a whole unsharded value of the full tile shape (takes its per-shard
    # sub-view), or a broadcast scalar
    if m.sharding: return m.sharding == sharding
    return m.shape == () or tuple(m.shape) == tuple(target.shape)
  if all(can_handle(m) for m in root.src):
    # every src either has the target sharding or is whole on every shard: run the alu per-shard
    srcs = [m.src[0] if m.op is Ops.UNSHARD else m if m.shape == () else shard_subview(m, target) for m in root.src]
    return srcs[0].alu(root.op, *srcs[1:]).unshard(target.arg, target.src[1:])
  # resharding: single-axis fallback via shard_srcs
  axis = root.axis
  assert axis is not None
  srcs = shard_srcs(root.src, axis)
  return srcs[0].alu(root.op, *srcs[1:]).unshard(axis, next(m.src[1] for m in root.src if m.op is Ops.UNSHARD))

def reduce_multi(root:UOp, multi:UOp):
  op, num_axes = root.arg
  sharding = multi.sharding
  reduced = [(ax, rng) for ax, rng in sharding if ax < num_axes]
  remaining = [(ax, rng) for ax, rng in sharding if ax >= num_axes]
  local = multi.src[0]._rop(op, tuple(range(num_axes)))
  if reduced:
    assert not remaining, f"partial allreduce not supported for multi-axis sharding {sharding}"
    # all sharded axes are reduced: full allreduce
    if ALLREDUCE_CAST and multi.src[0].op is Ops.CAST and multi.src[0].src[0].dtype in (dtypes.bfloat16, dtypes.half):
      orig_dtype = multi.src[0].src[0].dtype
      return local.cast(orig_dtype).allreduce(op, multi.device).cast(local.dtype)
    return local.allreduce(op, multi.device)
  # no sharded axes reduced: piecewise, keep all remaining sharding
  new_axes = tuple(ax - num_axes for ax, _ in remaining)
  new_rngs = tuple(rng for _, rng in remaining)
  return local.unshard(new_axes, new_rngs)
  • alu_multi: if every source has the same sharding (or is a scalar, or is a whole unsharded value of the full shape — it takes its per-shard sub-view), peel the UNSHARDs, apply the op, re-wrap. Otherwise fall back to shard_srcs: gather the odd source with copy_multi and re-shard it on the target axis.
  • reduce_multi: reduce locally first (_rop on the shard). If the reduced axes include the sharded one, the local results are only partial → local.allreduce(op, devices). With ALLREDUCE_CAST, a bf16/half value cast up for the reduce is sent in its original narrow dtype to halve traffic. If the sharded axis survives, no communication: re-wrap with the axis shifted.
  • Movement ops (reshape_multi, permute_multi, expand_multi, pad_multi, shrink_multi) translate the global movement into the local one and recompute the sharded axis. Shrinking or padding across the sharded axis is mostly unsupported.
  • COPY of a sharded value → copy_multi: to a single device, MSELECT(i) every shard, copy it, and cat them back; to a device tuple, pad each shard into place and allreduce(ADD).

And a second matcher, replace_allreduce, cleans up the device-level plumbing:

def lower_broadcast_copy(c:UOp, x:UOp):
  if not (isinstance(c.device, tuple) and isinstance(x.device, str)): return None
  if (sx:=x.simplify()).device is None: return UOp(Ops.MSTACK, src=(sx,)*len(c.device))
  return UOp(Ops.MSTACK, src=tuple(x.pad_to(x.max_shape).contiguous().copy_to_device(d) for d in c.device)).shrink_to(c.shape)

replace_allreduce = PatternMatcher([
  # BROADCAST: explicitly expand broadcast copies and combine with MSTACK
  (UPat(Ops.COPY, name="c", src=(UPat(name="x"),), allow_any_len=True), lower_broadcast_copy),
  # COPY_TO_ONE: if copying from multidevice to one, MSELECT the first (TODO: a little from each?)
  (UPat(Ops.COPY, name="c", src=(UPat(name="x"),), allow_any_len=True), lambda c,x:
    (m if (m:=x.mselect(0)).device == c.device else m.copy_to_device(c.device))
    if isinstance(c.device, str) and isinstance(x.device, tuple) else None),
  # MSELECT on MSTACK is replaced with nothing
  (UPat(Ops.MSELECT, src=(UPat(Ops.MSTACK, name="mstack"),), name="ms"), lambda mstack, ms: mstack.src[ms.arg]),
  # move shrink before MSTACK
  (UPat(Ops.SHRINK, src=(UPat(Ops.MSTACK, name="ms"),), allow_any_len=True, name="shrink"), mstack_early_shrink),
  # move MSELECT before movement/ALU ops
  (UPat(Ops.MSELECT, src=(UPat(GroupOp.Movement, src=(UPat.var("s"),), allow_any_len=True, name="v"),), name="ms"),
   lambda s,v,ms: v.replace(src=(s.mselect(ms.arg),)+v.src[1:])),
  (UPat(Ops.MSELECT, src=(UPat(GroupOp.ALU, name="a"),), name="ms"), lambda a,ms:
   a.replace(src=tuple(s.mselect(ms.arg) if isinstance(s.device, tuple) else s for s in a.src))),
])
UOpmeaning
UNSHARD(x, r…), arg = axeslogical view: x is shard r; the full value is the concatenation along arg
COPY(x, [r]), arg = device(s)copy x to a device, or to every device of a tuple (then it carries the DEVICE range)
MSELECT(x), arg = ithe single-device lane i of a multi-device value
MSTACK(x0, x1, …)the opposite: build a multi-device value from one single-device value per device
ALLREDUCE(x), arg = (op, devices)combine the per-device values with op; result on devices (tuple: every device gets it)

19.4One kernel, n launches: _device_num

After multi_pm, the per-device computation is still one graph, parametrized by the DEVICE range. Rangeify keeps that range open ("open DEVICE ranges are fine, they are bound per device at launch", rangeify.py:322), so a whole multi-device kernel is a single CALL whose buffer args are MultiBuffers. In codegen, the DEVICE range becomes a kernel argument:

tinygrad/codegen/gpudims.py — pm_device_to_var
pm_device_to_var = PatternMatcher([
  # the DEVICE axis is not a program axis, it's bound per device at launch. lower it to the _device_num variable (like SPECIAL for devices)
  (UPat(Ops.RANGE, name="r"),
   lambda r: UOp.variable("_device_num", 0, r.vmax, dtype=r.dtype) if r.axis_type is AxisType.DEVICE else None),
  # ENDs that closed a DEVICE range no longer close it
  (UPat(Ops.END, name="e"), lambda e: e.replace(src=(e.src[0],)+tuple(s for s in e.src[1:] if s.op is not Ops.PARAM))

and at run time exec_kernel iterates over the lanes of the MultiBuffers, binding _device_num to the lane index:

tinygrad/engine/realize.py — unwrap_multi
def unwrap_multi(call:UOp, resolved:list[UOp]) -> Iterator[tuple[list[Buffer], dict[str, int]]]:
  bufs = [b.buffer for b in resolved]
  if not any(isinstance(b, MultiBuffer) for b in bufs): yield cast(list[Buffer], bufs), {}
  else:
    # the DEVICE axis is bound per device at launch: it's a RANGE in the AST and the _device_num variable after codegen
    # on x86 the params aren't PARAMs in the body, so also check the PROGRAM's kernel_params
    has_dnum = ((isinstance(call.body.arg, ProgramInfo) and any(p.arg.name == '_device_num' for p in call.body.kernel_params)) or
                any((x.op is Ops.RANGE and x.axis_type is AxisType.DEVICE) or (x.op is Ops.PARAM and x.arg.name == '_device_num')
                    for x in call.body.toposort()))
    lanes = max(len(b.bufs) for b in bufs if isinstance(b, MultiBuffer)) # a single buffer is shared by every lane
    per_lane = [b.bufs if isinstance(b, MultiBuffer) else (b,)*lanes for b in bufs]
    for j, per_dev in enumerate(zip(*per_lane)): yield list(per_dev), {"_device_num": j} if has_dnum else {}

19.5COPY between devices

A cross-device COPY UOp becomes a buffer plus a store (copy_to_anon_store in prepare.py: "copies are always cross device: pad to the max shape so the copy reads a whole buffer"), and finally a copy CALL in the LINEAR: CALL(STORE(PARAM0, PARAM1), dst, src). Its arguments use MSELECT(i) to pick one lane of a MultiBuffer as the source, and MSTACK to assemble per-device single buffers into a multi argument for the next kernel. exec_copy then does a host memcpy (CPU↔CPU) or an allocator _copyin/_copyout; on HCQ devices it is a copy-queue command (DMA engine), possibly peer-to-peer, possibly staged through host memory (stage_copy).

tinygrad/schedule/multi.py — copy_multi
def copy_multi(multi:UOp, device:str | tuple[str, ...]):
  sharding = multi.sharding
  if isinstance(device, str):
    # reconstruct by concatenating along each axis from last to first
    piece_info: list[tuple[tuple, UOp]] = []
    for i in range(len(multi.device)):
      idxs = tuple(_shard_idx(r, i) for _, r in sharding)
      piece_info.append((idxs, multi.src[0].mselect(i).copy_to_device(device)))
    for j in range(len(sharding) - 1, -1, -1):
      ax, rng = sharding[j]
      groups: dict[tuple, list[tuple[int, UOp]]] = {}
      for idxs, p in piece_info:
        key = idxs[:j] + idxs[j+1:]
        groups.setdefault(key, []).append((idxs[j], p))
      piece_info = []
      for key in sorted(groups):
        grp = sorted(groups[key], key=lambda x: x[0])
        piece_info.append((key, grp[0][1].cat(*[x[1] for x in grp[1:]], dim=ax)))
    return piece_info[0][1]
  # multi-device target: unshard all axes and allreduce
  val = multi.src[0]
  for ax, rng in sharding:
    bsz = val.shape[ax]
    val = val.pad(tuple((0,0) if a != ax else (bsz*rng, bsz*int(rng.vmax) - bsz*rng) for a in range(len(val.shape))))
  return val.allreduce(Ops.ADD, device)

19.6Allreduce: naive, ring, all-to-all

An ALLREDUCE is expanded early in scheduling: earliest_rewrites calls create_allreduce_function, which wraps handle_allreduce in a precompiled CALL named "allreduce" — so the same allreduce pattern is scheduled once and reused.

tinygrad/schedule/allreduce.py — handle_allreduce (the node-level hierarchical path, lines 22–28, omitted)
def handle_allreduce(buf:UOp, red:UOp) -> UOp|None:
  if not isinstance(buf.device, tuple): return None
  ndev, shape, numel = len(buf.device), buf.shape, prod(buf.shape)
  op, device = red.arg

  # ring allreduce doesn't provide a benefit with only 2 nodes or where number of elements is less than 256k (empirically)
  # fallback to naive allreduce to save on kernel dispatch, chunking and reassembling chunks.
  concrete = all_int(shape)
  use_all2all = concrete and (ALL2ALL >= 2 or (ndev > 2 and numel > getenv("RING_ALLREDUCE_THRESHOLD", 256_000) and ALL2ALL >= 1))
  use_ring = concrete and not use_all2all and (RING >= 2 or (ndev > 2 and numel > getenv("RING_ALLREDUCE_THRESHOLD", 256_000) and RING >= 1))
  if DEBUG >= 2: print(f"{'ALL2ALL' if use_all2all else 'RING' if use_ring else 'NAIVE'} ALLREDUCE {ndev}x{numel} | {buf.dtype}")

  buf = buf.pad_to(buf.max_shape)
  # contiguous before we copy it
  buf = buf.contiguous()
  # naive: copy to all devices. if you shrink later, that'll be handled
  if not use_ring and not use_all2all:
    return functools.reduce(lambda x,y: x.alu(op, y), [buf.mselect(i).copy_to_device(device) for i in range(ndev)]).shrink_to(shape)

  # chunk data into ndev pieces
  assert isinstance(numel, int)
  factor = next((f for f in [32, 16, 8, 4, 2] if numel % f == 0), 1)
  base, left = divmod(numel // factor,  ndev)
  chunks = list(itertools.pairwise(itertools.accumulate([(base + 1) * factor] * left + [base * factor] * (ndev - left), initial=0)))

  # reduce-scatter
  reduced_chunks:list[UOp] = []
  for i,(s,e) in enumerate(chunks):
    if use_all2all:
      chunks_on_i = [buf.mselect(j).reshape((numel,)).shrink(((s,e),)).copy_to_device(buf.device[i]) for j in range(ndev)]
      reduced_chunks.append(functools.reduce(lambda x,y: x.alu(op, y), chunks_on_i))
    else:
      chunk, reduced = buf.reshape((numel,)).shrink(((s,e),)), buf.reshape((numel,)).shrink(((s,e),))
      for step in range(ndev-1):
        src, dest = (i+step)%ndev, (i+step+1)%ndev
        cp = (reduced.mselect(src) if isinstance(reduced.device, tuple) else reduced).copy_to_device(buf.device[dest])
        reduced = cp.alu(op, chunk.mselect(dest).copy_to_device(buf.device[dest]))
      reduced_chunks.append(reduced)

  # allgather
  copied_chunks:list[UOp] = []
  for i,rc in enumerate(reduced_chunks):
    if isinstance(device, str): copied_chunks.append(rc.copy_to_device(device))
    elif use_all2all: copied_chunks.append(UOp.mstack(*(rc.copy_to_device(buf.device[j]) for j in range(ndev))))
    else:
      chain:list[UOp] = [rc]
      for step in range(ndev-1):
        chain.append(rc := rc.copy_to_device(buf.device[(i+step)%ndev]))
      copied_chunks.append(UOp.mstack(*(chain[(j-i+1)%ndev] for j in range(ndev))))

  # reassemble
  return UOp.usum(*[c.pad(((s,numel-e),)) for (s,e),c in zip(chunks, copied_chunks)]).reshape(shape)

The decision:

  • Naive (default for 2 devices or ≤ 256 000 elements): every device's buffer is copied to the target and folded with op. With a device tuple as target, lower_broadcast_copy turns each copy into an MSTACK of per-device copies: \(n(n-1)\) cross-device copies of the whole buffer. Fewest kernels, most bytes.
  • Ring (\(n>2\) and \(N>\)256 000, or RING=2): cut the flattened buffer into \(n\) chunks (sizes multiples of the largest of 32/16/8/4/2 dividing \(N\)). Reduce-scatter: chunk \(i\) starts on device \(i\) and walks the ring \(i \to i{+}1 \to \dots\), each hop adding the local piece — after \(n-1\) hops it's fully reduced on device \(i{-}1\). Allgather: walk it around once more, \(n-1\) hops, leaving a copy everywhere. Every device sends \(2(n-1)\cdot N/n\) elements instead of \((n-1)\cdot N\).
  • All-to-all (ALL2ALL): every device sends chunk \(i\) directly to device \(i\), which reduces it, then broadcasts it — fewer sequential steps, more simultaneous links.
  • Finally the chunks are padded back into place and summed (UOp.usum) — a cheap way to concatenate.

The 3-device run below (RING=2 forces the ring for a tiny 6-element tensor) matches the demo with devices=3, elements=6 exactly: copies CPU→CPU:1, CPU:1→CPU:2, CPU:2→CPU (hop 1 of chunks 0, 1, 2), add kernels, the second hop, then the allgather copies, and finally the two "reassemble" kernels on all three devices.

With 4 devices and \(N\) elements, how many elements does each device send in a ring allreduce vs the naive one?
Ring: \(n-1\) reduce-scatter hops plus \(n-1\) allgather hops, each moving one chunk of \(N/n\). Naive: the whole buffer to each of the \(n-1\) others. The ring's advantage grows with \(n\) — at the cost of \(2(n-1)\) sequential steps, which is why it only kicks in for big buffers.

def describe(a):
  """walk a CALL argument down to its storage: MSELECT(i) picks lane i of a multi buffer, MSTACK stacks per-device buffers"""
  chain = []
  while a.op in (Ops.MSELECT, Ops.SHRINK, Ops.BITCAST, Ops.RESHAPE):
    if a.op is Ops.MSELECT: chain.append(f"MSELECT({a.arg})")
    a = a.src[0]

  return {"via": chain, "device": dev_str(a.device)}

def capture(label, code, tensor):

Some things the viewer shows that are easy to miss in text:

  • shard: two kernels on CPU produce the two shards (each a contiguous slice), then one copy sends shard 1 to CPU:1, and a final multi-device kernel writes both into the MultiBuffer (its second argument is an MSTACK of the two single-device buffers).
  • reduce sharded axis: local partial sums (one CALL on both devices), two cross copies, then the adds — the naive allreduce with \(n=2\).
  • data-parallel matmul: one copy (broadcasting w), one kernel on both devices. That's why data parallelism is the default way to scale training: the forward pass needs no communication; gradients of replicated weights are summed by an allreduce in backward.
  • gather: s.to('CPU') copies only the shard that isn't already on CPU (MSELECT(1)), then concatenates.

19.8Hammer it again: training with shards

The data-parallel recipe from examples/beautiful_mnist_multigpu.py (see also Chapter 20):

if __name__ == "__main__":
  X_train, Y_train, X_test, Y_test = mnist()
  # we shard the test data on axis 0
  X_test.shard_(GPUS, axis=0)
  Y_test.shard_(GPUS, axis=0)

  model = Model()
  for k, x in nn.state.get_state_dict(model).items(): x.to_(GPUS)  # we put a copy of the model on every GPU
  opt = nn.optim.Adam(nn.state.get_parameters(model))

  @TinyJit
  def train_step() -> Tensor:
    with Context(TRAINING=1):
      opt.zero_grad()
      samples = Tensor.randint(getenv("BS", 512), high=X_train.shape[0])
      Xt, Yt = X_train[samples].shard_(GPUS, axis=0), Y_train[samples].shard_(GPUS, axis=0)  # we shard the data on axis 0
      # TODO: this "gather" of samples is very slow. will be under 5s when this is fixed
      loss = model(Xt).sparse_categorical_crossentropy(Yt).backward()
      opt.step()
      return loss

Note x.to_(GPUS): Tensor.to with a device tuple is copy_to_device(tuple) — a replicated value with no UNSHARD, the same thing shard(GPUS) with axis=None produces.

  • The loss's mean() reduces over the sharded batch axis → reduce_multi → allreduce of a scalar.
  • Each weight gradient is a reduction over the batch axis of something sharded on that axis → an allreduce per weight. This is where ring allreduce (big weights, many GPUs) pays off.
  • Weights replicated (to_(GPUS) / axis=None) and updated by identical computations stay bit-identical on every device.
  • Sharded tensors work with TinyJit: _prepare_jit_inputs takes t.uop.src[0] of an UNSHARD, i.e. the MultiBuffer, as the input (jit.py:89).
You shard a (64, 1024) activation on axis 0 over 4 devices and call .reshape(64*1024). Then .reshape(4, 16, 1024). What's the axis after each?
reshape_multi finds the new axis whose prefix product equals prod(shape[:axis]) = 1 → axis 0 in both cases, and checks divisibility (65536 % 4, 4 % 4). A reshape like (64,1024)→(1024,64) would also keep axis 0 here; one that moves elements across shards raises.
Which operation on x = t.shard(devs, axis=0) causes no cross-device copies?
Elementwise then a reduce over axis 1 (not the sharded one): alu_multi then the piecewise branch of reduce_multi. The other two need an allreduce or a gather.

Chapter summary

  • t.shard(devs, axis) = COPY to all devices → SHRINK by a RANGE(DEVICE) → UNSHARD(arg=(axis,)); axis=None replicates. Storage is a MultiBuffer (one Buffer per device).
  • multi_pm (run first in prepare_rangeify) pushes ALU, movement, reduce, store, cast… through UNSHARD; mismatches reshard via copy_multi.
  • Reducing over the sharded axis → local reduce + ALLREDUCE; handle_allreduce picks naive (≤2 devices or small), ring (reduce-scatter + allgather over \(n\) chunks) or all-to-all.
  • MSELECT(i) picks a lane, MSTACK assembles lanes; cross-device COPYs become copy CALLs executed by exec_copy (or a DMA queue).
  • A multi-device kernel is one CALL launched per device; the DEVICE range becomes the _device_num kernel argument, bound by unwrap_multi.
  • Data parallel (batch on axis 0, weights replicated) needs no communication in forward; backward allreduces every weight gradient.
